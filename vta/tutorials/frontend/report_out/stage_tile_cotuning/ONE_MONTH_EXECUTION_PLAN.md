## 目标与贡献边界

| 贡献 | 问题 | 主要证据 |
|---|---|---|
| C1 资源与边界代价感知切图 | CPU/VTA stage、island、线程 | 搜索正确性、候选质量、边界消融 |
| C2 跨 Executor 双 slot 零拷贝 | 安全交接、减少复制 | 所有权、generation、多张量原子交接、物化字节 |
| C2 增强：共享缓冲复用（产物沿用 C3-S 前缀） | 利用已有存储、减少额外分配 | 别名安全规则、实际高水位、性能保护 |

按用户最新选择，共享缓冲复用并入 C2，不再以独立第三创新点为目标。
复用编译器已有存储信息，补跨 Executor、多帧交接的安全绑定，不复现 USMP 通用规划。
原 C3 的 CPU/FPGA DDR 争用探索保留：57 个复现条件下所测 wait 策略都更慢，
不等于不存在物理争用；本轮不恢复门控控制器。
用户接受少分配且吞吐不明显退化，不要求 FPS 提升；少分配指 u-dma-buf
池内实际占用下降，不等于释放系统预留的 192 MiB。

冻结计算二进制、量化、tile、线程、all-shared K2 和交接协议。
不实现 K1、动态 slot 深度、mixed copy/shared、通用 planner 或硬件改造。
FuseOps、量化、packing、AutoTVM 是复用的编译基础；本文搜索 stage/device、island、线程，
当前并未联合搜索 dtype/layout/copy/shared/K。

## 当前主任务：编译期传输签名引导的安全 AutoTVM（2026-09-10）

不重新做无界 AutoTVM，也不以超过官方 TopHub 为成立条件。固定 bitstream、量化、模板、
线程和 TopHub 哈希，研究：在 stage 搜索确定 VTA workload 集合后，怎样用固定硬件约束、
lowered TIR 的 DMA 请求形态以及 instruction/uop 足迹过滤高风险配置，以更少板端测量完成
incumbent-protected 微调，再把被安全接受的 stage 时间反馈一次给 DP。

现有起点已经冻结：Top-20 的 39 个 VTA stage placement 合并为 10 类唯一 workload，
按 workload 复用将原本 312 次 stage×config 测量降为 80 次（-74.36%）。80 个
TopHub incumbent/单轴邻域测量中 32 个正确、41 个编译失败、7 个数值失败、0 个达到
至少 2% 加速的安全替换。合法配对中，`tile_w` 改动使 LOAD 请求、LOAD payload 和运行时间
中位数分别变为 4.5×、4.173×、3.374×。这些证明有过滤信号，但尚未证明一个无泄漏的
过滤器能在未见 workload/config 上节省测量，因此还不能直接称为新创新点。

只执行以下闭环，预算 3–4 个工作日：

1. 冻结现有 80 点、TopHub、硬件和编译源码哈希；按 workload 分组划分开发/验证集，禁止
   同一 workload 的配置跨集合泄漏。
2. 在开发集上定义确定性两级规则：L0 检查 tensorize 整除、地址/对齐、片上 SRAM 与
   5376/5632 B 命令容量；L1 从最终 TIR 提取 LOAD/STORE calls、payload、平均请求、
   input/weight reload、stride 和 instruction/uop，按 Pareto 支配生成 shortlist。
3. 在冻结验证集回放三基线：随机/原始单轴邻域、只做合法性过滤、合法性+传输签名。
   报告编译失败和数值失败避免率、慢配置识别、板端测量数、incumbent regret；不把同一
   workload 内配置当作独立泛化样本。
4. 若验证集有额外预测力，再预注册最多 3 个代表 workload、每类 incumbent 加 2–4 个
   未测候选进行前瞻板端确认。所有候选先逐元素正确，再计时；TopHub 始终保留，候选只有
   正确且至少快 2% 才形成 overlay。
5. 用安全 overlay 更新 VTA segment 成本并重跑一次 DP，报告 Top-20 是否变化以及测量预算。
   即使 0 个替换，也可报告“过滤无效/危险测量并保护强基线”；不能声称性能提升。

若 grouped validation 不优于廉价合法性或 knob-only 基线，立即降为 VTA/ResNet18 case study，
不继续上板扩样。该方向与共享内存的联系限定为显式 DMA 共享 DDR 流量和 u-dma-buf 命令
工作集约束，不把片上 SRAM、host backing 和跨 Executor slot 混为同一种内存。

## 已冻结支路：共享队列容量—性能权衡（2026-09-08 至 2026-09-10）

目标是在冻结 A/B/C/D、tile、线程、bitstream、K2 的条件下，寻找正确性通过且
稳态 II 退化单侧 95% 上界不超过 2% 的最小**已验证**队列配置，不声称全局最优。
空间（池内实际分配/高水位）与时间（II/FPS/时延）分别报告。192 MiB 系统预留不变。
减少队列预留不等于减少张量 DMA；增加提交也不必然使张量 DMA 变碎。

1. Q0：独立诊断 runtime，默认指令/微指令队列各 32 MiB。增加
   `VTA_INSN_BUFFER_BYTES`、`VTA_UOP_BUFFER_BYTES`，不修改全局 `VTA_MAX_XFER`。
   测冷启动、warmup、八种输入、双 slot 和所有 VTA stage 的最终指令字节、
   实际序列化微指令峰值、提交原因、准备/复制/缓存维护/MMIO/设备等待。
   诊断可关闭；设备等待不是纯 DMA 或 compute stall。四拓扑独立进程。
2. Q1：各队列取四拓扑最大峰值的两倍，至少 4 KiB，向上对齐 256 B，上限默认容量。
   不改变提交批次，核对提交次数和指令/张量传输计数；复制/提交前检查全部容量，
   包括 FINISH 和重放。容量不足报错，不在线扩容或隐式分批。
3. Q2：先审查依赖和微指令生命周期，再开放独立软阈值
   `VTA_INSN_SUBMIT_THRESHOLD_BYTES`。只在已证明安全的位置提交。
   使用默认 backing buffer 扫描原最大指令批次的 1/2、1/4、1/8、1/16，
   按指令对齐、去重、排除不可容纳最小安全批次的值；再按实测峰值配置实际容量。
   软阈值不是分配容量。无安全位置或需改硬件/编译器/Executor 架构则停止 Q2。
4. 候选先做逐帧数值对照，再每拓扑一块 ABBA（302 帧丢前两帧）预筛选。
   在各拓扑 II 点估计退化不超过 2% 的候选中选总分配最小者，平局优先提交少者。
   若无额外空间收益，保留 Q1。冻结后每拓扑至少 1000 帧压力；不以预筛选声称无损。
5. 正式 E=external/default、P=anchor/default、F=anchor/最终队列配置；分别 E↔P、P↔F。
   三 boot、每拓扑每比较每 boot 五块 ABBA、302 帧丢前两帧。按块配对、boot 汇总，
   对 boot 平均 log-II 差计算单侧 95% t 区间。失败不使用同批结果反复选参。
   原 S2 强制慢消费者/异常退出/多张量/数值反例验证缺口继续保留。

Q0/Q1 三工作日上限，Q2 最多再一日，仍受原总预算约束；不扩展硬件预取。
可选逻辑池预算验证另记为未实施，不能将高水位直接冒充最小系统预留容量。
交付容量—性能曲线、提交计数、准备耗时、正确性与失败样本、推荐配置及余量。
当前状态：Q0 默认容量诊断、Q1 四拓扑 32 帧对照及容量拒绝通过；
64 MiB 队列缩至 16 KiB，实际总池内高水位下降 82.23%–86.96%。
Q1 每拓扑 1000 帧自然压力通过，全部测试进程已退出；
Q2 收尾后闭合审查、四档实际阈值资格测试及一 boot 预筛选已完成。Q1 首个独立 boot 的
E/P/F 性能实验完成：每拓扑、每比较 5 个 ABBA 块，共 160 runs，输出检查全部通过。

## S0 静态审计与真实分配基线：1–2 日

冻结 A/B/C/D（rank01/05/07/13）graph、参数、二进制和运行库 SHA-256。
逐边输出 entry、storage-id、容量、dtype/device、全部别名、读写节点、参数/常量身份、
跨边存储冲突，以及 eligible/rejected/unknown 和具体理由。

首版只借 CPU→VTA consumer 输入池：无其他 entry 别名、非参数、接口匹配、
零拷贝绑定覆盖全部输入使用。其他方向、linked parameter 和未知情况保留 external-K2。
consumer 用 slot1 时 producer 写 slot0，原池不得被 consumer 内部临时 entry 读写；
单帧最后使用时间不是跨帧安全证明。

只读驱动快照在图及参数加载后、slot 分配后、warmup 后、稳态后记录，区分原池、新增 slot、
padding、其他运行时分配。观察操作不得分配 u-dma-buf。每模式独立进程，避免 bump allocator
的 no-op free 和历史分配污染。

S1 门槛：至少一个明确安全类别，实际基线可核对非零预测节省，无未解决生命周期风险。
否则停止借池路线，不转通用 planner。

## S1 固定 K2 来源规划与实现：约 3–4 日，须先通过 S0

- 安全边借原池作 slot0，仅新增 external slot1；其余边保留两个 external slot。
- 多张量必须全部合格且互不冲突，否则整边回退；禁止同时存活的边重复借同一池。
- 可选 `--shared-buffer-plan`，不传保持旧行为。记录 package 哈希、边界/tensor/storage-id、来源和理由；哈希不匹配拒绝启动。
- 启动检查物理范围和对齐，失败在运行前整边回退并记录；不在线切换来源。
- runner slot 构造接入，四态、generation、bundle 不变。持有原 owner，不单独 free 借用内存；slot 引用先于所属 Executor 销毁。
- 原 runtime、runner、package 保留，实验独立部署。两模式同一新 runner，先验证关闭优化复现旧路径。

## S2 验证：约 2–3 日

### 正确性与拒绝案例

- 单元测试：独占输入、内部别名、参数池、跨边冲突、多张量部分合格、哈希不匹配、未对齐、范围越界。
- 显式验证 slot1 消费期间 producer 写 slot0 的交错。
- A/B/C/D 原/新路径逐帧对照，固定种子的不同输入，包含既有数值反例。
- 每拓扑至少 1000 帧压力，覆盖慢消费者、slot 交替、多张量、异常退出；输出一致，无提前复用、死锁、重复释放。

### 分配与性能

- 各拓扑报告新增 slot 字节、总高水位及各自节省比例；192 MiB 预留另列。
- 实测与预测含对齐逐字节一致；稳态不持续增长。
- 三独立 boot，每拓扑每 boot 五个 ABBA 块，A=external-K2，B=pool-anchor-K2。
- 每 run 302 帧，丢前两帧；沿用稳态 II、FPS、submit-to-complete P95 定义。
- 分配诊断、压力与性能分开；相同输入、二进制、线程、日志，profiler 时间不是 FPS。
- ABBA 块而非帧为统计单位，保留各 boot 及失败样本，不挑选结果。

### C2 缓冲增强验收（保留原量化门槛，不再据此拆分贡献）

至少两个冻结拓扑实际新增 slot 分配下降 ≥20%，报告总高水位下降；其他拓扑不隐去且分配不增加。
安全判定及分配规则可执行、可复用，全部正确性与回退测试通过。
各拓扑 II 相对退化单侧 95% 区间上界 ≤2%；区间不足则不声称无损。
覆盖或收益不足如实作为平台 case study；无论是否达到门槛，均不重复拆分 C2 的协议贡献。
