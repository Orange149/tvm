# 有效性排序与容量预筛组合：保留零增益结论

用12个其他几何池的288个编译标签训练固定128树RF有效性代理，输入为knob、
几何、模式，不使用目标48候选的结果训练。排除目标workload与训练身份重叠。
目标候选已在P7R369暴露，本次是回顾性组合探索，不是前瞻确认。

| 排序 | 获得前4个合法点的编译调用 | 加容量预筛后 |
|---|---:|---:|
| RF有效性排序 | 4 | 4 |
| Random，100 seed中位数 | 21 | 6 |

RF已经把合法点排在最前，容量规则在这个目标上的首4合法点指标没有额外收益。
不能声称已经证明增强ML2Tuner冷启动。Random的gross候选数中位数仍为21，
预筛减少的是编译调用，不是随机顺序中考虑过的候选数。

若强制完整遍历，编译调用48→14，合法点8个全部保留；但这不是固定质量
停止时的收益，不得用完整遍历节省覆盖首4点零增益的事实。

RF不是ML2Tuner原Model P/V/A链，也不是Rieber邻域初始化；没有latency标签、
最终质量或time-to-performance-target评价。代码训练时间未计入比较，故不报
时间加速。下一步需要真实搜索预算和性能目标，不能继续只靠合法点数量论证。
