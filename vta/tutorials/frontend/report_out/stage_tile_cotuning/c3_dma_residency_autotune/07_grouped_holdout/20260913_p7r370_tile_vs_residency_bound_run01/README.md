# 普通tile容量与驻留生命周期容量的增量消融

同一P7R368冻结48候选，实际执行三种策略；顺序为baseline/tile/residency/
residency/tile/baseline，六个独立进程。所有成功candidate_id与TIR哈希集合
一致（各8个），没有候选替换。

| 策略 | 实际lowering尝试 | 两轮完整子进程秒 |
|---|---:|---|
| 不预筛 | 48 | 2.783650 / 2.574250 |
| 普通tile容量 | 24 | 2.288948 / 2.132712 |
| 驻留生命周期容量 | 14 | 2.016376 / 2.058998 |

普通tile容量已经排除24个不可能点，故之前48→14不能全部归因于驻留建模。
驻留范围的净增量是在普通容量筛选后再排除10个点，即剩余lowering尝试降低
41.67%。本次两轮平均进程墙钟约2.211→2.038秒，降低约7.8%；小样本描述性
结果，不是统计显著或端到端AutoTune收益。

普通tile基线使用相同单位、硬件容量与作用域限制，但容量计算不扩展驻留
生命周期；真正instantiate的候选和模式完全不变。它是机制消融，不能标成
stock AutoTVM、HW-Aware Initialization或ML2Tuner的复现。

候选已在P7R369实际编译，本次属于已有池受控消融，不新增未见候选证据。
预筛代码单元测试4项通过。独立文献方法和完整调优对照仍未由本实验补齐。
