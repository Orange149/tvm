# Y08：tile、驻留与共享内存流量的分离分析

证据来源：P7R356/qualification/static_results.jsonl、candidates_v2.jsonl。
范围：YOLOv3-tiny conv12，CI=512、CO=1024、13×13、3×3；仅静态编译证据。
没有读取新的 FPGA 标签，不修改 P7R355 协议或 P7R357 搜索顺序。

## 1. 等字节对的请求差异全部来自 STORE

两个 input-stationary 候选仅 tile_co 从 4 改到 32；tile_h=13、tile_w=1、
tile_ci=1，两个 virtual-thread knob 均为 1。

| 指标 | F02 input | F06 input |
|---|---:|---:|
| 输入 LOAD 字节 / 次数 | 246,272 / 416 | 246,272 / 416 |
| 权重 LOAD 字节 / 次数 | 61,341,696 / 416 | 61,341,696 / 416 |
| 输出 STORE 字节 / 次数 | 173,056 / 208 | 173,056 / 26 |
| 每个 STORE 的字节 | 832 | 6,656 |
| 总字节 / 总逻辑请求 | 61,761,024 / 1,040 | 61,761,024 / 858 |
| 手写 ACC 必要容量界，vectors | 52 | 416 |
| 手写 weight 必要容量界，vectors | 36 | 288 |

LOAD 请求大小直方图也完全一致。因此总请求数减少 182（17.5%），不是输入或
权重预取优化，而是输出分块变大、STORE 次数减少 87.5%。总输出量不变。
这些次数是编译器逻辑二维 DMA 调用，不能当作 AXI burst 数。

仅在请求开销串行、STORE 每次固定开销相同且其他项不变的简化模型中，
可写预测差值 ΔT_store≈182 L_store。不能用实测算子时间差除以 182 就声称
测到了 AXI 启动延迟：tile_co 同时改变计算分块、UOP、片上占用以及重叠机会。
该配对可检验 bytes-only 是否遗漏性能差异，不能独立识别请求数的因果效应。
上板后先三 seed 正确性，再沿冻结协议计时；任一失败都不得形成速度对比。

## 2. 改空间 tile 能比仅做输入驻留更显著地减少搬运

F01→F02 只把 tile_h 从 1 改到 13（其余 knob 不变）。两个模式中权重流量均
从 797,442,048 B 降至 61,341,696 B，即下降 92.31%；weight reload 从 169
降为 13，与空间 tile 数从 13×13 降为 1×13 相符。这是空间复用，不是
weight_resident_barrier：两者 residency drain 都为零。

original 的输入量从 11,214,848 B 降至 3,940,352 B；input-stationary 从
700,928 B 降至 246,272 B。输入并非简单除以 13，因为 3×3 邻域重叠和边界
padding 改变了有效输入重复量。ACC 必要界从 4 增至 52 vectors，input
必要界从 9 增至 45 vectors；不能将此手写必要界冒充真实 allocation 峰值。

## 3. 输入驻留的收益取决于原有输出通道分块

same-tile original→input-stationary：

- F02：输入量 3,940,352→246,272 B，降低 93.75%；权重量不变。
- F06：输入量 492,544→246,272 B，降低 50%；权重量不变。

CO 的 packed block 数为 1024/16=64。tile_co=4 时外层输出通道块数为16，
tile_co=32 时为2。输入驻留消除这部分重复加载，所以两个模式对应的输入
流量比恰为16和2。增大 tile_co 已经减少一部分输入重放，驻留的边际收益
随之下降；不能把两个收益百分比相加。

权重字节不变但逻辑 LOAD 次数下降，说明“合并请求”和“消除重复数据”必须
分开统计：例如 F02 weight calls 6,656→416，单请求 9,216→147,456 B。

## 4. 对搜索方法的约束

以上三条是当前编译实现的可核对规律，不声称首次提出，也不代替真实硬件
性能。支持将 input/weight/output 分项字节、分项请求和容量边界保留为诊断
量；暂不支持修改冻结排序或宣称新增特征一定提高搜索效率。

F02/F06 input 的 bytes 相同，现有 bytes 排序按 candidate_id 打破平局，恰好
与 calls 排序首选相同。即使 F06 上板更快，本池也不能证明 calls 策略相比
bytes 策略更早找到它。应报告该识别限制，而不是事后改 tie-break。
