# 冻结规则后的额外候选验证

P7R368在计算预筛结果和lowering之前冻结48个候选（16 family ×3 mode），
固定按ConfigEntity index的哈希排序选择，不使用预筛结果挑点。排除C3目录
内全部索引到的candidates_v2.jsonl身份；这是已有Y08几何的额外候选，不是
新网络/新几何，也不能保证未索引历史资料从未覆盖这些实体。

容量规则SHA256与P7R368预注册一致：
4364c55826d64225f529f04ef1ac09c3787bf8185ac3f39f3591be3dd5893915。
未根据结果修改规则或替换候选。baseline实际lower全部48点，包括预筛拒绝点。

四个独立进程按baseline/prescreen/prescreen/baseline顺序运行：

| 策略 | 进程墙钟秒 | lowering尝试 | 成功 |
|---|---:|---:|---:|
| baseline | 2.728268 | 48 | 8 |
| prescreen | 1.960762 | 14 | 8 |
| prescreen | 2.085893 | 14 | 8 |
| baseline | 2.690555 | 48 | 8 |

四轮成功身份及其TIR哈希集合完全相同。预筛减少34次lowering尝试（70.83%），
没有观察到误删成功点。平均进程时间由约2.709s降为2.023s（本次约25.3%），
仅为这四轮描述性结果，非统计显著或通用保证。完整搜索成本、FSim和FPGA
性能均不在本实验范围内。

这比开发记录回放增加了“规则冻结后对额外配置实际编译”的证据，但仍局限
于原有几何与当前编译器。不能用它替代跨硬件、跨几何验证或完整AutoTune对照。
