# R50B额外候选：冻结驻留规则的三臂lowering验证

P7R373在编译前按固定哈希选出16family×3模式，排除已索引v2池中的身份。
规则SHA256保持4364c55826d64225f529f04ef1ac09c3787bf8185ac3f39f3591be3dd5893915，
与Y08额外池相同，没有重调规则或替换失败点。

| 策略 | lowering尝试 | 成功数 | 两轮完整子进程秒 |
|---|---:|---:|---|
| baseline | 48 | 19 | 2.667769 / 2.526793 |
| 普通tile容量 | 45 | 19 | 2.490662 / 2.526930 |
| 驻留生命周期容量 | 40 | 19 | 2.412121 / 2.437780 |

六轮成功身份和TIR哈希集合全部一致。驻留规则拒绝的8个均在baseline实际
触发allocation超限。相对普通容量规则的净增量是再减少5次lowering（45→40），
而非48→40全部归因于驻留。两轮均值约2.509→2.425s，本次描述性差值约3.3%，
重复数不足以主张统计显著。

相比Y08的24→14净增量，本几何45→40较小，说明容量过滤收益依赖候选
分布和几何，不能统一写成大幅加速。原R50B几何已用于开发，但新增身份未在
本次索引到的历史v2池中出现；不是新几何、整网、FPGA或完整AutoTune实验。
19个lowering成功不等于数值正确，FSim/FPGA资格仍未由本实验覆盖。
