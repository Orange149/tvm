# P7R146--P7R154：Y03 第二前瞻池会话记录

## 目标与标签隔离

本轮目标不是超过 TopHub，而是在新的 YOLO conv8 几何
`CI=128, CO=256, H=W=26, K=3` 上，复制 Y00 的完整池协议，验证冻结的共享内存访问规则能否以更少
试验找到同一 FPGA-correct 池内的最优候选。候选生成、合法性门和搜索排序均在读取 Y03 FPGA
正确性及性能标签前冻结；TopHub 不参与生成、排序或 oracle 定义。

## P7R146--P7R151：候选空间与资格

- P7R146 枚举完整 1280 ConfigEntity 域，185 个通过手写容量/复用谓词；按确定性哈希冻结 8 个 family，
  未使用 static DMA 数值、FSim、板端、TopHub 或性能标签。
- P7R147 的 8 family × 3 mode 共 24 个身份全部 lowering 失败。该结果表明手写容量谓词遗漏了 padding、
  allocation 和 compact 2D DMA 等编译约束。
- P7R148 run02 仅用 original 的真实 lowering 合法性重冻结：在 185 个粗筛候选中扫描 73 个，65 个
  lowering 失败，最终得到 8 个 original-lowerable family；扫描墙钟 57.321 s。run01 的 harness
  `family_id` 错误和 run02 一并保留，不用于候选结论。
- P7R149/P7R150 因本地 FSim 配置/pkg-config 缺失而失败，是环境失败，不能分类为候选 invalid。
- 恢复完全相同的 FSim 环境后，P7R151 的 24 个身份中 17 个 static-pass、13 个三 seed FSim-pass：
  original/input/barrier 分别为 6/6/1；存在一个三模式完整 family。

## P7R152--P7R154：冻结、交叉编译与板端全池

- P7R152 在板端标签前冻结全部 13 个 FSim-pass 身份、20 seeds、budget 1/2/4/8 和各搜索策略。
- P7R153 的健康探针与 13 个候选全部交叉编译成功，未接触板端或性能标签。
- P7R154 在 boot `1d260256-086b-4bf5-a834-4092e773acea` 完成：13/13 候选通过三 seed FPGA
  correctness，共 39/39 correctness invocations；13 × 7 共 91/91 timed calls 正确。
- pool oracle 为 candidate `7b5e10e4...`（original），中位延迟 11.528215 ms。
- 运行时复用同一组 shape-compatible output/data/weight 缓冲，并保持已资格化的
  output-data-weight 分配顺序。

## 搜索结果

budget=1 的 pool-oracle+2% 成功率：

| 策略 | 成功率 |
|---|---:|
| Random | 0% |
| stock knob-XGB | 15% |
| paper same-tile minimum-access | 10% |
| 静态 DMA-bytes | 100% |
| 复杂 shared-memory lexicographic | 100% |

DMA-bytes 和复杂 lexicographic 再次同序，因此 calls、padding、submission 和 command 特征不形成独立
排序贡献。正式方法收敛为“real lowering/FSim 门 + 静态 DMA 总字节优先 + FPGA correctness”。

budget=8 时，DMA-bytes 为 673.198 MiB LOAD、151,100 DMA calls、60 FPGA invocations、
24,197.150 ms；stock knob-XGB 为 1,174.937 MiB、276,330 calls、40 invocations、31,188.118 ms。
DMA-bytes 降低数据流量和墙钟，但因部分驻留候选拆成多次 submission，FPGA invocation 反而更多。

## 同 tile 机制结果

四个 input-stationary/original 对和一个 weight-barrier/original 对全部更快：

| 模式 | 延迟改善 | 逻辑 LOAD 变化 | DMA calls 变化 |
|---|---:|---:|---:|
| input pair 1 | 68.04% | -32.39% | -88.24% |
| input pair 2 | 60.22% | -6.79% | -88.24% |
| input pair 3 | 22.73% | -1.44% | -70.59% |
| input pair 4 | 12.69% | -3.09% | -47.06% |
| weight-barrier pair | 80.61% | -97.80% | -47.04% |

这些结果说明减少 LOAD 通常有利，但加速幅度不与 LOAD bytes 线性对应，DMA 调用形态、同步和计算调度
仍共同决定延迟；驻留规则必须和 tile 绑定，不能写成所有卷积都固定选择某一种模式。

## 两个前瞻池合并口径

Y00 和 Y03 共 24 个 FPGA-correct 候选、40 个 replay seeds。budget=1 时，DMA-bytes 40/40 命中池
oracle+2%；Random、stock knob-XGB、paper minimum-access 的合并成功率分别为 7.5%、10%、15%。
aggregate budget=8 下，DMA-bytes 相对 stock knob-XGB 的逻辑 LOAD、DMA calls、五阶段墙钟分别下降
42.13%、49.24%、15.34%，FPGA kernel invocations 增加 25%。

公共资格开销必须单列：Y03 的 24 模式 static/FSim 分别为 103.236/12.222 s，之前的 lowerability
重冻结扫描另需 57.321 s。逻辑 LOAD/STORE 是 VTA runtime 计数，不是物理 AXI burst。

## 当前结论边界

该结果支撑“面向固定 FPGA 的、编译器可执行性门控的共享内存流量优先调优”作为较强硕士论文创新点，
并构成 CCF-C 风格 case-study 的主要实验骨架。尚不能主张全 AutoTVM 搜索空间的全局最优、在线自适应
tuner、整网 FPS、物理 AXI 流量或跨网络普适性。下一项必做工作是 selected allowlist 的不足命令容量
fail-closed 部署验证；整网/stage 或第三网络验证属于增强项。
