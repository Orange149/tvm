# C3 驻留—指令组织实验计划 v1.1

确认日期：2026-10-12。执行依据：本线程最后确认的 v1.1；旧治理计划仅作历史证据，不替代本协议。

## 一、创新点与证据边界

创新点：面向固定 VTA，结合容量受限的权重驻留与分组命令组织，生成安全的部分驻留程序，并通过受控实验及局部经验模型，解释减少搬运与程序组织代价之间的取舍。

不把驻留、双缓冲或命令合并的一般思想称为首次提出。新增贡献是具体的 VTA 程序生成、地址与依赖处理，以及完整融合函数中的验证。

本轮保持节点24、六个程序、单启动，不增加 Tile、任务、预取、搜索器或整图测试。

| 证据 | 回答的问题 |
|---|---|
| 四个紧凑 R 程序的实测 | 保留更多权重，实际是否更快？ |
| F13-B→R13-G | 相同驻留下，命令及相关 μop 组织改善有多少收益？ |
| R8／R12 留出预测 | 固定紧凑组织下，驻留方向的局部线性近似是否合适？ |

模型不承担跨组织泛化、自动选优或普适规律的证明。

## 二、冻结程序与比较资格

固定 YOLOv3-tiny-224 节点24完整四参数融合合同：128→256、14×14、3×3，16组权重，每组18 KiB；WGT SRAM为256 KiB。

四个紧凑程序统一使用 `b1h2w14ci1co1`、单线程、一个流式槽、整组 LOAD、每组一个乘加 kernel，以及现有空间边界桥和函数末同步。

常驻集合冻结为前 R 组：组 `0…R−1` 使用固定槽 `0…R−1`；组 `R…15` 按原顺序共用槽 R。常驻内容仅在本次完整融合调用内有效，下次调用重新建立。

| 程序 | 常驻权重 KiB | 含流式槽名义分配 KiB | 预期 WGT LOAD | 预期请求载荷 KiB |
|---|---:|---:|---:|---:|
| R0-G | 0 | 18 | 112 | 2016 |
| R8-G | 144 | 162 | 64 | 1152 |
| R12-G | 216 | 234 | 40 | 720 |
| R13-G | 234 | 252 | 34 | 612 |
| F13-B | 234 | 252 | 34 | 612 |
| Input-7×7 | 不适用 | 实际证书 | 实际命令 | 实际命令 |

请求次数按最终循环核对：`N_WGT_LOAD = 16 + 6(16−R) = 112−6R`。表中是指令请求载荷与名义分配，不是实际总线流量或容量证书。R0-G是全部轮换的分组控制，不等于现有 Input。

### 旧二进制与新变换的比较门禁

R13-G明确为历史孤立融合候选 `f13_g` 的显示别名；继续使用封存二进制。历史整图中的 F13-G属于不同封装，记录对应关系，不要求 graphlib 哈希相同。

新实验变换支持冻结 R 集合，不改变旧入口默认行为。其 R13 分支只生成本地回归产物，不成为第七个板测程序。必须与封存 R13 核对完整 ABI、融合语义、计算顺序、归约、RESET、后处理、INP／ACC／输出请求及覆盖范围、WGT地址、kernel、token与同步关系。

仅允许变量名、函数符号等无关差异；不能规范化掉地址、归约或同步差异。比较不匹配时暂停，不替换旧锚后继续宣称同一组织。

F13-B与R13-G另外形成比较证书：权重布局、装载和其他数据请求匹配；列出 GEMM 合并直接引起的 μop、指令、依赖及提交变化。存在无关差异时，不进入预定组织收益比较。

## 三、资格、调用边界与单启动协议

新增独立入口 `run_vta_c3_residency_tradeoff.py`，提供 `prepare / qualify / board / analyze`。全部新产物独立保存，历史记录不覆盖。

### 本地与板端资格

新程序先通过三个 seed 的完整融合 FSim，并取得以下证据：

- INP／WGT／ACC基址及全部循环偏移形成的有效地址范围。
- 单 kernel 长度、UOP引用区间及冻结 runtime 分配／刷新安全证据。
- 上一组最后读取完成→新 LOAD 覆盖→新组读取开始的依赖关系。
- 删除常驻 LOAD 后，token生产、消费及跨提交关系仍成立。

缺少必要证据即停止上板，不以 unknown 替代通过，也不以 push/pop 总数相等替代依赖证明。

随后六程序分别进行三 seed FPGA 校验及 A→B→A 检查。后者固定输入和加法参数，在同一 RPC、模块、权重句柄内原地写入 A、B、A；中间不重载 bitstream、模块或增加清理同步。先证明完整参考输出不同，再逐次比较。

### 单次计时与统计接口

复用已验收的四参数单次 helper：计时外取得函数、更新参数与输出哨兵；计时内调用一次完整融合函数，包含内部命令组织、全部提交与现有函数末完成等待；计时外保存轻量 profiler 快照，再读取并校验输出和输入参数。

RPC往返、函数查找、分配、上传、参考计算和输出校验不计入时延。禁止 `time_evaluator`、隐式预热及额外同步。每单元三个正式调用的 helper 计数必须依次为1、2、3。

修正旧 runner 在输出读取后才取 profiler 的顺序，避免计时外复制混入调用统计。冻结 runtime 原有计数开销保留，不事后扣除。

`MAC push` 定义为非 RESET 的 GEMM kernel 推送；现有 `push_gemm_op_calls` 包含 RESET，不能直接代入模型。通过最终 TIR、命令语义分类与轻量总数交叉检查：F13-B预期总推送1008＝RESET112＋MAC896；四个紧凑 R 程序预期224＝112＋112；Input预期12＝4＋8。不满足对应关系时停止使用该模型特征，不临时改计数含义。

### 诊断与正式计时

诊断独立执行，不插入正式会话。覆盖首次调用，以及三个 seed 轮换顺序下“三次预热＋第4／5／6次调用”的逐次命令状态；不得额外预热到另一种稳定状态再解释正式时间。

标签固定：`A=F13-B，B=R13-G，C=R0-G，D=R8-G，E=R12-G，F=Input-7×7`。

```text
A B F C E D
B C A D F E
C D B E A F
D E C F B A
E F D A C B
F A E B D C
```

每个轮次×程序使用统一 fresh RPC、bitstream初始化和长期存活的参数句柄；三个 seed 各预热一次，再各计时一次。同轮 seed 顺序相同，六轮循环两遍。seed固定为 `0、20250901、20260910`。

规定正式计时108次、预热108次；资格、A→B→A、诊断及基础设施另记。逐调用日志包含会话、程序、轮次、seed、调用类别、唯一调用ID和状态，底层提交归属到对应调用。

错误、超时、身份变化、设备非独占、CPU3执行条件不满足或非预期完整调用时停止，不透明重试或拼接。频率、温度只作辅助记录，不依据结果临时增加排除条件。

本轮不重启 Linux 或开发板；只允许冻结协议规定的 bitstream 重载和 fresh RPC 初始化。

## 四、模型与统计规则

统一聚合：`m[r,p] = median_seed(t[r,p,seed])`，`T[p] = median_round(m[r,p])`。主表、拟合及验证均使用上述聚合，单位为 ms。

### 模型拟合与留出验证

固定模型：`T_hat = a + b*N_WGT_LOAD/34 + c*N_MAC_push/112`，`a,b,c >= 0`。

校准程序为 R0-G、R13-G、F13-B；验证程序为 R8-G、R12-G。Input不进入模型。

先检查实际计数构成的设计矩阵秩，保存奇异值和条件数，采用标准 SVD 数值容差。秩不足则标记 `MODEL_UNIDENTIFIABLE`，保留完整程序比较，不更换特征。若正式调用状态下无法获得一致特征口径，模型标记资格未决。

NNLS触及零系数时保存活跃约束和校准残差，不改成另一种回归。a仅称经验截距，b/c是综合程序变化的经验系数，不解释为独立硬件成本。

在预期计数、约束未触边界时，`T_hat[R8] = T[R13] + 5/13*(T[R0]−T[R13])`，`T_hat[R12] = T[R13] + 1/13*(T[R0]−T[R13])`。验证的是驻留方向局部插值，不验证组织系数 c 的泛化。非负 b 预设预测单调，不能用预测结果证明实际驻留越多越快；零训练误差或训练 R²=1也不是模型成功证据。

分析先仅读取校准数据，封存数据哈希、系数、残差、计数定义和验证名单后，再解封验证时延。中间不显示验证排名。

两个验证点均满足绝对相对误差≤10%，才称局部近似通过；同时报告带符号误差百分比和绝对误差 ms。该门槛不代表能分辨2%的性能差异。

### 实测比较与候选筛选

配对改善：`g[r](C;B) = 100*(1−m[r,C]/m[r,B])`。报告六个改善值的中位数和未四舍五入的胜场；平局不算胜。不以总体中位数之比替代配对指标。

新增候选列为后续确认对象须同时满足：相对 R13-G 中位改善≥2%，赢至少5/6轮；相对 Input 的配对中位改善>0，另报胜场。第二项仅表示本轮中位方向更快，不自动构成可靠实用增益。筛选不是统计显著性检验。

另报 R0→R8、R8→R12、R12→R13相邻比较。驻留趋势完全依据实测，不要求出现中间最优点。
