# C3 官方调优程序上的有效窗口聚合研究目标

研究名称为“片上数据有效窗口约束的VTA跨微内核聚合方法”，属于《面向DNN的嵌入式异构计算共享内存技术研究》的第三个研究点。前两个研究点解决CPU/VTA任务划分及共享DDR缓冲交接；本研究检查数据进入VTA独立片上区域之后，计算命令是否仍有可以安全撤除的微内核边界。

研究目标是：在固定硬件、完整融合计算和统一运行条件下，对官方TopHub调优缓存配置重实例化的程序进行数据有效窗口约束的跨微内核聚合，验证能否进一步降低完整算子调用时延。保持原Tile、虚拟线程、张量装载安排和后处理，只主动改变GEMM与μop组织。容量和必要依赖是约束，不预设μop装载是瓶颈。

## 研究故事与已有工作

已有分块、输入复用、权重驻留和双缓冲决定数据怎样搬入、怎样重复使用。数据还有效时，一组计算可能因代码生成作用域而分成多个小微内核。本研究检查哪些边界可以撤除，哪些边界承担换装、累加阶段或必要通知，必须保留。

原始[VTA](https://arxiv.org/abs/1807.04188)已经支持一个GEMM引用多个μop及硬件循环，也已有作用域和依赖处理。“一个命令执行多个μop”不是本研究新增能力。[Banerjee等](https://arxiv.org/html/2111.15024#S4.SS4)的TPS、双缓冲、冗余装载消除、runtime μop优化和性能实验均为实质性方法；不能说它没有考虑数据、容量、依赖或性能。就论文描述而言，未见其将本研究限定的三问组织为独立的自动跨微内核聚合与分段方法，但不由此推断作者代码或全部其他研究没有相关实现。[Cheng](https://doi.org/10.1016/j.future.2025.108165)研究输入优先、片上权重复用，也涉及μop生成及重复处理，具体差异需要方法和编译产物证据。

通用循环融合、生命周期分析和内存规划已有充分研究。候选贡献在于把数据版本、ACC阶段和实际依赖用于真实VTA命令形成，给出受限支持域内可执行的判定、分段及公平性能证据。CPU/VTA共享的是DDR；INP、WGT、ACC和UOP SRAM是独立区域，本方法属于后端执行优化，不称为新的共享DDR管理机制。

## 能不能合

检查读取的是正确数据版本，旧读取完成先于覆盖；每个输出收到相同乘积项及重数；归约整数语义允许重排；ACC按初始化、累加、后处理和观察阶段检查；必要FIFO/token先后保持。新增连接点和硬件循环进位还需硬件依赖依据。未知关系保守保留边界或拒绝，不开发通用程序证明器。

## 能合多少

固定顺序下逐次尝试连接最长合法前缀，在加入下一kernel前检查容量、有效地址、字段表示、模式、硬件循环和缓存签名。单kernel超8192条基址μop不能由减小聚合量修复；连接后超限则分段。合法kernel放不进当前SRAM尾部时，runtime可以从0重新分配，这称为回绕，不是自动拆分超大kernel。host缓存、DRAM序列化及设备驻留分别认证，同一缓存身份内容不能变化。

## 合了值不值

同一官方配置产生原版B和自动版A，张量请求及完整融合语义保持一致，测量一次完整调用的组织、全部提交和等待。正式采用最小计数模式，独立详细诊断证明全部提交。允许无窗口、无收益和负结果，不把少发命令直接换算为硬件周期收益。

节点24已有结果保留为固定程序证据，其碎片部分来自本项目特化展开；不能据此断言原TVM普遍存在同类碎片。共同runtime的Q1/Q8 μop装载次数和载荷相同，收益不能归因于减少μop装载。较强TPS仍更快；TPS不是AutoTVM最佳程序，不隐去这项限制。

## 固定对象与PDCA

对象限于既有ResNet18-224和YOLOv3-tiny-416：分别20和12次VTA卷积、各11种workload。官方记录来自PYNQ，准确称为“官方TopHub缓存配置在当前AXU5EVB上的重实例化与重测基线”；原搜索预算未知。YOLO224未命中，不借用416配置。CPU首卷积不纳入研究。

P冻结来源和基线无变换往返；D实施受限窗口判定、容量分段及缓存认证；C先本地门禁再冻结最多四算子B/A小池，完整调用最多480次；A封存全部结果并收窄或保留主张。PDCA是研究管理流程，不计入技术创新。本轮不增加形状、Tile、驻留比例、预取、调优搜索、selector、切点性能搜索、硬件改造或整图部署，完成后暂停。
