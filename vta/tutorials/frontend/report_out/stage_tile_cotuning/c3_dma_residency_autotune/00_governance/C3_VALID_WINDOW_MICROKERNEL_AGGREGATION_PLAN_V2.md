# C3 片上数据有效窗口约束的 VTA 跨微内核聚合研究计划 v2

本研究是硕士论文第三个创新点的候选，目标是在既定张量数据安排下，判断哪些计算微内核边界可以撤除、必须在哪里分段，并量化聚合的净收益与适用边界。新增方法是否成立，取决于可检查的判定与变换，而不是节点24八段拼接后的加速数字。

当前执行范围只到方案修订。后续先完成边界来源、聚合等价依据及 TPS 静态审计三项本地交付；这些交付验收后，再决定是否实施既定五程序的单启动资格与计时。默认不重启开发板，不自动开展第二启动或整图实验。历史台账、程序、runtime 和原始结果保持不变。

## 1 研究故事与论文定位

前序工作确定 CPU 与 VTA 的任务划分及共享 DDR 缓冲交接。本研究在既定数据布局和调用边界下，研究加速器内部的计算命令组织：数据已经搬进片上且仍可使用时，相关计算是否必须保持原来的多个微内核边界。

CPU 与 VTA 共享的是 DDR。INP、WGT、ACC 和 UOP SRAM 是 VTA 的独立片上区域，不能互相借容量，也不是 CPU 与 VTA 直接共享的统一 SRAM。因此，本研究属于共享内存异构推理系统中的后端执行优化，不以改名方式宣称新增 CPU/VTA 共享内存管理机制，也不重复计算前序零拷贝、缓冲所有权或完成握手的贡献。

研究目标为：

> 针对 VTA 后端在既定数据复用安排下的细粒度微内核组织，研究基于操作数数据版本与依赖关系的跨微内核聚合。在保持张量数据请求、逻辑操作数对应关系和可观察计算结果不变的条件下，由计算语义、有效地址和微码表示约束确定聚合范围，实现保守分段与拒绝，并通过粒度对照及实用基线比较，量化完整调用的净收益和适用边界。

### 用三个问题说明研究内容

这里的“合”，就是把多个小微内核的 μop 清单组织成较少的 GEMM 命令，不是减少卷积的乘加计算，也不是改变权重驻留比例。本研究用三个问题说明要做什么：

**能不能合？** 数据、计算顺序和必要通知是否允许。

先检查输入和权重在被使用时是不是正确的那份数据，会不会提前被覆盖；再检查改变计算次序后，每个输出是否仍收到相同的乘积项、得到相同结果；原本需要通知装载或存储模块的位置，也不能随意推迟。只有这些条件成立，才能合，不能仅凭“几段计算挨在一起”就合并。

**能合多少？** 一份 μop 清单能装下多少，中途是否必须换数据或通知其他模块。

把小清单连接起来后，既要符合 μop 容量、指令表示和运行时缓存限制，也不能跨过必须换数据或发出必要通知的边界。遇到这些边界就停止或分段，不为凑成八段而强行合并。这里回答的是合法聚合范围，不是预先保证某个大小最快。

**合了值不值？** 组织开销减少后，完整算子到底快了还是慢了。

命令变少不等于整个调用一定变快，μop 装载和执行安排也可能带来新的代价。因此，要在相同张量数据请求下实测完整融合算子时延，而不是只数减少了多少条命令；再与较强的 TPS 程序比较，分别判断“聚合本身有没有收益”和“最后的程序是否有实用竞争力”。

对应的技术工作按以下顺序开展：

1. 追清原微内核边界的来源，区分局部代码生成边界与不可撤除的计算、数据或依赖边界。
2. 在明确支持域内，不依赖节点编号和变量名，自动判定、连接或分段兼容微内核。
3. 在张量请求固定时，对照不同聚合上限的完整调用时延、命令与 UOP 代价，并比较实用基线。

本研究不预设聚合越大越快、中间粒度必然最佳，或最终必然超过较强分块程序。

## 2 相关工作与增量边界

| 相关工作 | 已有能力 | 本研究需要证明的差异 |
|---|---|---|
| 原始 VTA 与 TVM 后端 | 一个 GEMM 已能引用多个 μop 并使用硬件循环；已有局部地址、依赖分析及作用域变换 | 不新增 ISA，也不把一个命令执行多个 μop 称为原创；说明既有生成流程为何仍保留特定边界，以及本变换撤除边界的条件 |
| Banerjee 等 | TPS 分块、双缓冲、冗余装载消除和 runtime 的 μop 优化；已报告部分程序因较高 μop 装载而变慢 | 不把命令组织重要或少搬数据未必更快当新发现；在共同优化基线上研究不同基址微内核的连接与合法分段 |
| Cheng 等 | 输入优先和片上权重复用，以减少冗余张量访问 | 数据复用思想是基础；具体聚合差异须用完整方法和编译产物对照，不由代码不可得推断作者没有实现 |
| 通用循环融合与静态内存规划 | 融合思想、生命周期分析和空间复用已有研究；USMP 主要安排内存池偏移 | 不重新设计通用内存分配器；候选增量是将已有有效性与依赖信息用于 VTA 跨微内核命令形成 |

最近的技术对照是 VTA 的微内核生成链、既有 scope/loop 变换以及 Banerjee 的编译和 runtime；USMP 只用于划清内存分配与命令组织的区别。已有地址与依赖分析本身不算新增机制。

## 3 五类取舍与本轮唯一优化轴

| 因素 | 要平衡什么 | 本轮角色 |
|---|---|---|
| 1 输入与权重复用 | 同一输入覆盖更多输出通道，或同一权重覆盖更多空间位置；遍历变化可能减少一类请求、增加另一类请求 | 固定计算范围、Tile 和遍历；核对四类张量请求，不新增大 Tile 搜索 |
| 2 常驻与流式空间 | 常驻更多可减少重装，但压缩换组或双缓冲空间 | 固定13组常驻加1个流式槽；覆盖关系限定窗口，不扫描驻留比例 |
| 3 装载粒度与启动机会 | 较大 LOAD 可减少装载指令，却可能增加首段计算所需的准备；小 LOAD 有不同命令和依赖代价 | 保持现有整组 LOAD，不新增预取，不改变首批张量准备 |
| 4 GEMM 与 UOP 组织 | 小内核分别发命令，或连接为较大内核；影响命令推送、单内核规模、UOP 装载和缓存 | 唯一主动改变的轴是最大聚合量 q |
| 5 安全等待与流水重叠 | 读完才能覆盖，但必要通知也不能随意推迟；更大命令可能改变后续可执行机会 | 保留必要事件关系；未知内部通知、覆盖或提交关系即切段或拒绝 |

前三类决定数据的可用布局和复用范围，第五类决定必要的读取与覆盖先后，这些条件共同限定第四类可以聚合的范围。五类取舍不是五个已识别的独立物理成本；本轮不拟合五因素时延模型、不开发 selector。

## 4 既有证据与必须更正的边界来源

### 聚合已有程序级正结果

旧 runtime 上，节点24固定小 Tile、相同13组常驻加单槽及张量请求，未聚合 F13-B 与聚合 F13-G 的启动1时延分别为6.190和4.965 ms。两启动配对改善约19.82%和19.57%，均6/6轮获胜。权重载荷同为612 KiB；MAC 为896到112，UOP LOAD 为148到36，累计 UOP 字节同为14,416，设备提交都为1。

这是固定程序上组织变化的净效果，不是权重搬运减少20%、设备启动减少或单一硬件等待的分解。旧整图只完成单启动：聚合图374.36 ms，实用 Input 图374.83 ms，仅差0.47 ms，不能说聚合带来20%整图加速。[算子报告](../07_grouped_holdout/20261009_c3_node24_group_gemm_run01/REPORT.md)、[第二启动与整图](../07_grouped_holdout/20261009_c3_node24_group_gemm_run01/BOOT2_AND_GRAPH_REPORT.md)。

### 较强程序仍然更快

共同补强 runtime 上，TPS 输出通道双缓冲 ci4 为3.254418 ms，13组常驻紧凑程序为5.008835 ms。后者时延约高53.9%，从后者出发需再降低约35.0%才追平 TPS。因此，固定小 Tile 的聚合效果与相对较强分块的实用竞争力必须分别回答，不能预设扫描 q 就能弥补差距。[基线报告](../07_grouped_holdout/20261013_c3_banerjee_baseline_completion_run02/REPORT.md)。

旧 runtime 与共同补强 runtime 的时间、命令统计和系数不拼接为消融。TPS 是本地补强的 Banerjee 式软件参照，不是作者全系统或 Original 全空间 oracle。

### 八段不仅来自原 TVM

本地源码明确显示：

- Tensor intrinsic 生成 `coproc_uop_scope`；原 VTA 构建流程已有 `LiftAttrScope`，随后 `FoldUopLoop` 在各个作用域内部折叠至多两层循环。
- 本项目 `Node24WeightSlots` 为使 CO 成为唯一动态 UOP 缓存键，显式把归约 k=0至7特化为八段。当前 `UopKernelMap` 接受空签名或一个 int 签名，并有键范围保护。这是本地实现要求，不是硬件只能做八个命令。
- 槽位特化产生的新作用域位于原 scope 提升之后；现有 `Node24GroupGEMM` 是节点名、变量名及八段形状特化的实验实现，还不是独立的窗口判定方法。

因此，不能把这些碎片全部归咎于原 TVM 或一般 VTA 后端。先追清 schedule、tensorization、本地特化与 pass 次序共同形成的边界。[槽位特化](</home/orange/code/tvm/vta/python/vta/top/vta_node24_partial.py:202>)、[缓存键限制](</home/orange/code/tvm/vta/runtime/runtime.cc:1544>)、[pass 顺序](</home/orange/code/tvm/vta/python/vta/build_module.py:69>)、[现有 FoldUopLoop](</home/orange/code/tvm/vta/python/vta/transform.py:42>)。

原有 `LiftAttrScope` 已能重组相同属性的连续片段。实施前必须对其与 `FoldUopLoop` 的实验性重新组合做静态结构核对：若已有 pass 组合直接覆盖所需能力，应集成已有能力，不包装为新算法；该本地检查不增加第六个板测程序。[原有作用域重组](</home/orange/code/tvm/src/tir/transforms/lift_attr_scope.cc:91>)。

## 5 有效窗口与聚合支持域

### 窗口是数据版本与依赖区域

窗口不使用毫秒时间戳。对 INP/WGT 的逻辑子块版本 v，使用冻结 FIFO、token 及顺序语义证明：

```text
LOAD完成(v) 先于每次读取(v)
最后读取完成(v) 先于下一次覆盖开始
```

数据版本以逻辑缓冲区、源子块、实际装载事件和 SRAM 映射绑定。同一流式槽装入下一组时，地址可以不变，但数据版本已变。保留常驻版本也必须证明本次调用确实建立过内容，不能依赖上次调用。

地址证据分三层：物理范围合法、指向正确逻辑子块、读取时保存正确数据版本。只检查基址不越界不能认证。

ACC 用累加阶段描述：RESET初始化、规定乘积项归约、后处理或输出观察。正常累加是合法内容更新，不要求 ACC 始终不变；另一次 RESET、其他阶段复用或提前观察构成边界。

### 首版只支持可判定的 GEMM 区域

支持常量有限循环、可解析的仿射地址、兼容模式与硬件循环参数，以及已能解释的 LOAD 和 token 关系。固定候选的首次使用条件可由有限循环和条件路径展开证明。

未知调用、动态分支、不可解析别名、内部必要通知或不可证明的覆盖关系均截断窗口或拒绝聚合；不建立通用 SSA 系统、任意程序证明器或新 runtime trace。

默认不跨 RESET、ALU/clip/cast、STORE、既有同步和已知提交边界。不得把内部等待全部搬到大 GEMM 前、通知全部搬到其后；保持 token 总数不是依赖等价证明。只连接已经证明内部没有不可移动事件的计算段。

候选位置仍在 `FoldUopLoop` 后、`CPUAccessRewrite` 前，但准备阶段必须核验此处仍能取得逻辑来源、实际地址和依赖。信息不足时，仅在实验编译链保留只读侧表并验证映射；无法恢复则停，不退回节点号或变量名匹配。函数符号可用于固定实验路由，不得代替可聚合性判断。

### q 是上限而不是凑数目标

依次扫描兼容区域，在加入下一微内核前检查数据版本、累加阶段、事件关系和微码表示。最多连接 q 个，合法窗口结束或表示能力不足时先结束当前段。即使 Q8 遇到六段合法窗口，也只能聚合六段；不能跨边界满足预计命令数。

检查单 kernel 长度、全部硬件循环展开后的有效地址及字段范围，同时绑定冻结 runtime 的 UOP 分配、回绕、驱逐和在途引用证据。累计 UOP 字节、单 kernel 大小和 SRAM 同时有效范围分开记录；不为制造容量边界而缩小硬件 SRAM。

## 6 等价依据与张量请求合同

### 归约重排依据

拼接后可能由“微内核外层、硬件循环内层”变为“硬件循环外层、多个基址 μop 内层”。共同循环参数不能单独证明等价。

本地按最终 μop 与硬件循环，核对每个输出对应的逻辑乘积项及重数：无遗漏、重复或错误操作数，RESET位置一致，中间结果没有被观察。采用有界枚举或仿射关系检查，不按运行时间猜测。

节点24卷积归约从零开始，每输出含128乘3乘3共1152个标量乘积项。int8保守界为：

```text
任意归约次序的部分和绝对值
不超过 1152 × 128 × 128 = 18,874,368 < 2^31 − 1
```

该界只用于卷积归约。后续 ADD 的位置、输入 ACC、位宽、右移、clip和cast必须保持原语义；不把上述界扩展为任意 int32 ADD 不溢出的保证。若后处理未重排且输入位模式相同，只需证明其整数语义相同，不额外要求所有可能 ADD 都无溢出。

本地等价检查不只依赖 clip 后的 int8 输出：检查展开计算的归约结果，并使用有正负、非零输出且不过度饱和的定向输入。可使用已有 FSim 能力，但不新增 FPGA ACC读取接口。正式程序仍为原四参数完整融合 ABI。

### 请求相同不只比较总量

Q1至Q8逐条比较规范化张量 LOAD/STORE：逻辑对象、相对偏移、元素单位、大小、步长、padding、条件路径、重数及必要先后。还核对融合语义和槽位映射；612 KiB或34条相同不足以证明装载了相同数据。

聚合允许改变 GEMM/μop 的表示及由此产生的控制指令、UOP LOAD和实际自动提交行为，但不得新增手工同步、张量重装或 spill。必要依赖须重新认证。比较 TPS 不要求张量请求相同，因为其 Tile和线程不同。

报告统一使用“张量数据请求不变”；指令流和 UOP 的载荷另列。不将指令数直接称为物理总线事务，不推断 DDR争用、Fetch饥饿或硬件等待周期。

## 10 分析规则与两种后续门槛

聚合口径固定如下：

```text
m[r,p] = 第r轮程序p的三个seed时延中位数
T[p]   = 六个m[r,p]的中位数
g[r,C;B] = 100 × (1 − m[r,C] / m[r,B])
G[C;B] = 六个配对改善g的中位数
```

主要对照预先固定为Q8对Q1。Q2/Q4用于描述粒度趋势；TPS用于实用价值判断。报告六个配对改善、胜场、轮次时延范围及毫秒差。平局按未四舍五入时延判定，不算胜。90次正式调用不是90个独立工作负载或启动，5/6轮与2%只是工程门槛，不是统计显著性。

主表同时列每程序实际分段、总调用时延、各类张量请求、MAC/RESET、UOP LOAD指令、累计UOP载荷、最大kernel μop、总指令和提交。已有设备等待及调用减等待差额只作诊断，不命名为纯CPU时间、硬件空闲或流水slack。

| 后续路径 | 预定条件 | 可支持的结论 |
|---|---|---|
| 固定Q8的研究复验 | 相对Q1的G至少2%，且至少赢5/6；不要求超过TPS | 可另行申请以相同二进制、runtime和协议做独立启动复核，回答固定程序聚合效应是否复现 |
| 实用候选与整图投入 | 从Q池按T最小封存候选；相对Q1的G至少2%、至少5/6，且相对TPS的G至少1%、至少5/6 | 可另订实用基线比较和图资格、图性能协议；当前仍只是单启动候选 |

Q池最小T精确并列时优先Q1，其余按冻结program ID。Q2或Q4的探索性结果如实保留，不替换失败的主要Q8假设；其未来复验须明确为独立提出的假设，不利用后续数据重选。研究复验与部署可以使用同一个经批准的新启动，但不得自动增加启动次数。

第二启动只确认封存程序，不重新选q，不回灌结果。没有超过TPS时可以得到条件性聚合规律和研究复验结果，但不投入整图部署。旧runtime双启动不能补成新runtime双启动证据。

若进入整图，至少区分节点24用Q1、冻结聚合候选、TPS的图；其余实现与参数不变，先验证实际路由、前后衔接和所有输出。整图完整计时与独立启动判据另行冻结，不能从算子百分比推算整网FPS。FPS仅在实测整图后按1000除以中位毫秒数报告，明确为单图等效FPS。

验收分别判断方法、聚合效果和实用竞争力：

- 方法不能依赖节点24编号、变量名或固定八段才能正确判定；支持域外能保守拒绝，必要语义边界不能越过。
