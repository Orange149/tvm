# C3 共享输入提前归还试点 v1.1

本文件记录本轮执行合同；原计算图、生产 runner、GraphExecutor、runtime 和历史报告不修改。实验入口为 `vta/tutorials/frontend/run_c3_input_early_release.py`，阶段为 prepare / qualify / measure / analyze。完成或必要门禁失败后暂停，不自动重试、换对象或重启。

## 问题与固定对象

消费者读完共享输入但仍在执行后续计算时，提前归还使用权，是否能以一个输入槽接近双槽吞吐？这是可行性试点，不预设成功或首次生命周期分析。

固定原三阶段 ResNet18-224：`cpu-00-02_t4__vta-03-17_t1__cpu-18-20_t1`。以 `c3s_buffer_reuse/s0_static_run1/A.json` 绑定包文件。CPU→VTA 输入为 float32[1,64,56,56]，802816 B。stage1 节点1是唯一直接读者，产生独立 float32 中间结果；节点2才 cast/pack。

| 方法 | 目标边界 | 归还时机 |
|---|---|---|
| L1 | 原输入池单 anchor | stage 结束 |
| L2 | 原输入池＋一外部槽 | stage 结束 |
| C1 | 外部源→原输入池私有目的区 | 完整 CPU-view memcpy 结束 |
| E1 | 与 L1 相同 | 最后读者成功返回，紧邻节点2入口的实际地址检查通过后 |

其他 VTA→CPU 边界均为两个外部槽。提前归还是授权下一代写入，不是 free、重绑消费者或提前复用内部工作区。C1 在等待输出槽之前复制并归还；不以逐字节复制弱化基线，`AXU5EVB_DRIVER_SAFE_COPY=0`。

## 门禁与证据

本地核验原包哈希、entry/storage/ABI、完整软件路径及原 ARM 函数和实际 TVM 同步线程池返回语义。未知别名、入口输出/carry、后续读取、异步保留指针或完成语义未决均拒绝。没有原 LLVM 时只用原 ELF，不重编译冒充原证据。

板端记录实际加载库、实际输入/中间结果/packed 工作区的虚拟与物理范围及线程亲和性；不能以 storage 编号不同替代物理范围证据。归还后不再检查旧输入内容。四臂相同轻量代理原样转发，目标调用一次，异常不归还；stage 末不得重复归还已释放的旧 generation。

执行前保守细化：公开接口无法在节点1内部取得节点2尚未调用时的真实输出参数。因此 E1 在节点1正常返回后，于紧邻节点2入口完成真实范围验证，立即归还，再执行节点2。中间没有其他计算、复制或同步；分别记录 last_reader_return 与 release，不宣称在返回瞬间归还。串行参考同样装代理但不提前归还；仅 L2 代理关闭校准不产生该次调用的内部范围证据，由其随后同身份代理开启资格补齐，不能把这个豁免用于 E1 正式运行。

本地测试包含 stale/duplicate/missing release、abort、ABI 转发、隐藏读者拒绝、逐边槽数、FIFO 与账目。原生 LeaseBook 自测与板端使用同一状态机，不只测试理想化模型。

板端资格固定为：串行参考100帧；四方法各32帧；E1 两个三帧确定性屏障测试；L2 代理关/开各5预热＋16采样。事件分别验证“读前不能覆写”及“读后、stage 完成前可完成下一帧生产”。代理校准完成窗 FPS 扰动超过2%则停止，不扣除常数。

任何输出错误、超时、非法归还或身份变化均全局停止，不继续后续板测，不补样。

## 单启动正式协议

不主动重启。仅在 RAM 恢复冻结 bitstream、192 MiB udmabuf 与工具；环境不满足则暂停，不改频率、不写 SD、不终止外部服务。

CPU 配置：stage0 两线程 CPU0–1；stage1/VTA 一线程 CPU3；stage2 一线程 CPU2。进程 taskset 允许0–3；不使用覆盖逐 stage 分核的全进程 affinity 选项。固定队列深度2、关闭额外 CPU gate；线程 spin、优先级与 driver 等待配置各臂一致。

根目录 `n02123597` 按文件名字典序取前100张 JPEG，沿用原224预处理；冻结图片与输入哈希，不按性能挑图，不作为分类准确率测试。

| 轮次 | 顺序 |
|---|---|
| 1 | L1→L2→E1→C1 |
| 2 | L2→C1→L1→E1 |
| 3 | C1→E1→L2→L1 |
| 4 | E1→L1→C1→L2 |

每方法块独立进程、同一 bitstream 初始化；正式 actors 上流水预热5帧并排空，保持同一线程/TLS/模块/缓冲后采样100帧。输出复用前复制到预分配普通主机快照，成本共同计入；比较、JSON 和写盘在流水结束后。正式期不打印命令、不逐节点 profiling、不查询分配快照。

以毫秒为单位，FPS=1000×99/(c100−c1)，II=(c100−c1)/99。帧时延为入队请求到稳定完整输出，另报中位/P95，不与 FPS 互取倒数。

总账：参考100＋资格128＋事件6＋代理42＋正式预热80＋正式采样1600＝1956帧，5868次 stage graph 调用。基础设施自测另列。正式 C1 复制400次，每次802816 B。

192 MiB 系统预留、DMA 实际 bump 分配高水位、普通主机验证内存分别报告；高水位不是动态活跃内存。

## 判定与交付

单启动继续门槛：全部正确/账目/lease/环境证据通过；E1 对 L1 四轮配对 FPS 改善中位数≥5%、至少3/4胜；对 L2 和 C1 分别满足 FPS 比值中位数≥0.98、至少3/4轮≥0.98；E1 无目标边界新增复制，相比 L2 少一份实际外部槽；事件证明下一帧真正使用了提前归还的槽。
