# R18-H1 T8 首次使用分阶段全权重驻留实验

日期：2026-09-23。状态：`ONE_BOOT_DEVELOPMENT_COMPLETE`。

## 结论

P4-S 已正确实现并完成一次启动的板端开发测量。它保留与 P4-E 相同的完整权重驻留范围、T8 Tile、
双输出虚拟线程、计算上下文、非权重请求、SRAM arena 和函数结束同步，只把权重从“算子开头全部装入”
改为“每个归约组首次使用时装入固定位置，后续空间块继续复用”。

这一改变确实减少了启动前置请求，但性能收益较小：

| 基线→测试 | 配对中位改善 | 胜/负轮 | 判定 |
|---|---:|---:|---|
| O2→P4-E | 0.686% | 6/0 | 未达到 2% 开发门槛 |
| P4-E→P4-S | 0.562% | 4/2 | 未达到 2% 开发门槛 |
| O2→P4-S | 1.211% | 6/0 | 未达到 2% 开发门槛 |

所以可以说“首次使用分阶段装载带来方向一致但较小的程序级改善”，不能说它已经形成稳定加速，
也不能将 0.562% 解释成精确的 DMA/计算重叠周期收益。当前证据只有一个层、一个 Tile、一个 boot。

## 实现与本地资格

新增实验模式 `weight_vthread_resident_staged`（mode 8）以及只由该身份显式安装的
`StagedWeightResidencyRewrite`。生产 mode 0 和已冻结 mode 6/7 不安装该 pass。

该 pass 在虚拟线程地址注入前验证 R18-H1/T8 的确切程序形状，然后：

- 将每线程 WGT 区从 4,608 B 扩展到 18,432 B，最终双线程 arena 为 36,864 B；
- 为四个展开的 `k_o` 分配互不覆盖的固定位置；
- 将每个 WGT LOAD 限定在第一个空间块执行；
- 将对应 GEMM 的权重地址改到同一固定位置；
- 不增加全局 drain 或额外提交。

9 项回归全部通过，包括 mode 8 单线程 fail-closed、三 seed FSim 精确输出、最终地址边界、依赖平衡、
首次使用顺序以及同一输入/权重/输出句柄连续更换权重的三次调用。三候选均通过 lowering、最终地址、
三 seed FSim、实际命令转储和 ARM 交叉编译。

## 编译后与实际命令证据

| 指标 | O2 | P4-E | P4-S |
|---|---:|---:|---:|
| WGT arena | 9,216 B | 36,864 B | 36,864 B |
| 权重请求 | 258,048 B / 56次 | 36,864 B / 2次 | 36,864 B / 8次 |
| 首个有效 MAC 前权重请求 | 9,216 B | 36,864 B | 9,216 B |
| 累计 UOP LOAD | 472 B / 10次 | 1,624 B / 16次 | 1,624 B / 16次 |
| 总指令 | 270 | 223 | 228 |
| 提交 | 1 | 1 | 1 |
| 显式额外 drain | 0 | 0 | 0 |

P4-S 没有进一步扩大 μop；其相对 P4-E 的命令代价是六个小权重 LOAD 替代两个大 LOAD，并因 NOP
变化形成净增加五条指令。由此可排除“分阶段实现再次复制大型 GEMM kernel”这一风险。与此同时，
P4-S 仍保留 P4-E 的 1,624 B μop 组织，因此它只修复装载时机，不解决完整驻留的 μop 代价。

## 板端合同

三版本使用同一 bitstream、fresh-completion runtime、单提交阈值、CPU3、长期复用参数句柄和三 seed。
诊断、正式计时分会话；正式计时执行六轮三版本全排列，每个候选组含三个单次调用，共54个样本。

- boot ID：`aac37acf-5ab2-441d-b9bd-7c335d302307`；
- governor：`userspace`；
- 正式预热：9 次；正式计时：54/54 正确；
- 全部诊断签名匹配；隐藏额外调用为 0；
- 板端算子调用中位数：O2 5.9530 ms、P4-E 5.9170 ms、P4-S 5.8809 ms。

耗时包含调用内命令组织、提交与完成等待，不包括编译、上传、参数准备和输出校验；不称纯硬件时间。
