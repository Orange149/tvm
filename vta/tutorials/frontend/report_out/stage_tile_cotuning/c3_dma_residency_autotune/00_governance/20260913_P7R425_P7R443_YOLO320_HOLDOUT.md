# P7R425--P7R443：YOLOv3-tiny-320 跨模型在线搜索与完整池报告

## 1. 结论

本轮把 C3 的 cheap-proxy/peeling 路径从 `relay.testing` ResNet50 扩展到真实 Darknet
YOLOv3-tiny 拓扑与权重，并在板端对 **全部 8 个图输出** 做逐元素等价检查。Y09 conv8 是
合法性负例：24 个预冻结身份仅 2 个通过 lowering/FSim，且没有完整三模式 family，因此按合同不
上板。Y10 conv18 则形成 12 个候选、4 个完整三模式 family；12/12 候选均通过三 seed 全图 FPGA
正确性和七轮交错计时。

Y10 的完整池 oracle 为 Y10F02 input-stationary（`dc939a...`），候选中位全图 latency 为
1056.143 ms、paired stock ratio 为 0.987878。prospective peeling 以 3/12 dispatch 命中 exact
oracle，较穷举的候选 build action、FPGA invocation、逻辑 DMA bytes/calls 分别减少
76.26%、75.00%、75.06%、75.08%。但简单 calls-lazy 和本次固定 Random 都在第一次 dispatch
命中 exact oracle；peeling 和 DMA-bytes 到第三次才 exact。四种方法第一次都已进入 oracle+2%。

因此本轮支持“跨模型可执行、全图正确、以较少候选达到池内最优”，不支持“peeling 普遍优于
简单 calls/Random”。

## 2. 无标签冻结与执行顺序

| 阶段 | 产物 | 结果与标签边界 |
|---|---|---|
| Y09 候选冻结 | P7R425--P7R426 | YOLO-320 conv8，完整 ConfigSpace 2880、硬件规则可选 476；未接触板端 |
| Y09 本地资格 | P7R427 | 24 gross 中 2 static/FSim-pass，仅 Y09F06 original/input；0 个三模式 family，不上板 |
| Y10 候选冻结 | P7R428--P7R429 | YOLO-320 conv18，完整 ConfigSpace 1280、硬件规则可选 180；未读取目标标签 |
| Y10 本地资格 | P7R430 | 24 gross 中 12 static/FSim-pass；Y10F00/F02/F04/F06 均为完整三模式 family |
| 前沿与控制冻结 | P7R431 | 三点 wave0；完整 bytes/calls/Random/fixed-front 顺序在板端标签前冻结 |
| 多进程执行合同 | P7R432、P7R434 | 600 s；peeling 自适应，三个控制各固定 3 候选；P7R434 绑定修正后的执行器与 builder 哈希 |
| 在线执行 | P7R435--P7R438 | peeling、calls、bytes、Random 四条独立进程；运行时不读取 oracle |
| 事后完整池 | P7R439--P7R441 | 对 peeling 未派发的 9 点独立重建/重测，构成 12 点 oracle |
| 独立控制汇总 | P7R443 | 将完整池质量标签按不可变 candidate ID 事后连接到四条真实执行轨迹 |

P7R433 在板端 preflight 之前因 YOLO packed layout 被错误交给 ARM target 而失败，没有产生候选
正确性或 latency 标签。随后公共 builder 增加显式 `ext_dev_only` 模式，本地 stock dry-run 通过，
并重新生成 P7R434 合同后才开始 P7R435。P7R433 不计入有效实验。

## 3. Y10 完整池与在线搜索

- 模型：合同绑定的 `yolov3-tiny-320.cfg`、官方 Tiny 权重与 Darknet 动态库；三项内容均核对 SHA256。
- 目标层：conv18，CI256→CO128，10×10，1×1，stride1，padding0。
- 搜索池：4 个 tile family × original/input-stationary/weight-resident-barrier，共 12 点。
- 正确性：12/12 FPGA-correct；每候选三 seed，每次同时加载 stock 与 candidate，共 72 条候选/stock
  correctness 记录；每条记录检查 8 个图输出。
- 计时：每候选 7 轮平衡交错、stock/candidate 各一次，共 168 条计时记录；全部输出逐元素相等。
- 全过程保持 boot `4d232b6f-6e2a-4395-aafe-853a021403e8`，结束后 FPGA、默认 RPC 与存储健康门均通过。

prospective peeling 的结果为：wave0 三点全部正确，所以没有展开 wave1；第三点是 exact oracle，第一
点已进入 oracle+2%（regret 0.520%）。在线外层墙钟为 212.727 s。相对 12 点穷举的实测组件：

| 指标 | peeling 3 点 | 完整 12 点 | 减少 |
|---|---:|---:|---:|
| candidate dispatch | 3 | 12 | 75.00% |
| candidate build action | 34.104 s | 143.665 s | 76.26% |
| FPGA kernel invocation | 60 | 240 | 75.00% |
| 逻辑 DMA bytes | 14,485,919,232 | 58,083,585,024 | 75.06% |
| 逻辑 DMA calls | 13,875,927 | 55,686,084 | 75.08% |
| invocation host wall | 108.912 s | 436.283 s | 75.04% |

这些是 logical VTA runtime counter，不是物理 AXI burst。完整池的 9 点事后补齐另耗费 110.241 s
构建进程和 455.031 s 板端进程，它们是 oracle 审计成本，不属于在线搜索节省。

## 4. 四条独立在线轨迹

| 方法 | 3 点顺序的主要差异 | 首次 +2% | 首次 exact | 总墙钟 | 结论 |
|---|---|---:|---:|---:|---|
| peeling | 三轴 Pareto wave，错误时才剥离 | 第1点，89.591 s | 第3点，212.507 s | 212.727 s | exact，但本池无错误点、未展开 |
| calls-lazy | DMA calls 从小到大 | 第1点，89.683 s | 第1点，89.683 s | 213.908 s | 本池最佳简单规则 |
| bytes-lazy | DMA bytes 从小到大 | 第1点，91.502 s | 第3点，214.972 s | 215.206 s | 与 peeling 同身份/同顺序 |
| frozen Random | P7R431 固定随机顺序 | 第1点，89.500 s | 第1点，89.500 s | 214.260 s | 单次 seed 的偶然有利顺序 |

四条轨迹均为 3 dispatch、18 correctness invocation、42 timing invocation，且位于同一 boot；墙钟
差仅约 1.2%，不构成成本优势。Random 这里只是一个预冻结 seed，不能推导随机搜索的期望成功率。
calls 的首次 exact 是必须保留的反例：在 Y10 上，复杂 Pareto 保险没有带来更快 time-to-oracle。

## 5. 驻留机制在完整 YOLO 图中的表现

四个 family 的 input-stationary 都减少目标算子的 DMA，四个全图配对也都略微加速
（0.049%--1.424%）。weight-resident-barrier 将目标算子 DMA bytes 减少 34.13%--92.92%，但四个
全图配对中三快一慢：Y10F02 慢 0.115%。这再次复现 Cheng 论文的关键边界——最少访问不必然最快，
同步、submission 与计算重叠仍需真实硬件裁决。

由于一次只替换 YOLO 全图中的一个 conv18 调度，整图收益被其余层稀释是预期结果。本轮的价值是把
单算子 DMA 机制接到真实完整模型、真实权重、8 输出等价与全图 latency，而不是宣称 YOLO FPS 或
COCO mAP 已改善。随机输入只证明 schedule regression equivalence；未进行数据集精度评估。

## 6. 对创新点的影响

本轮关闭了此前“cheap proxy/peeling 只有 Relay-testing ResNet50、没有新 workload 同步独立控制”
的主要限制。现在可主张：同一共享内存语义搜索流程能够在 ResNet50 与 Darknet YOLOv3-tiny 两类
完整图上运行；Y10 以 3/12 候选保留 exact oracle，并具有真实完整墙钟、全输出正确性和三条独立
控制。

仍不能主张：

1. peeling 普遍优于 bytes/calls/Random；Y10 的 calls 和固定 Random 明确更早 exact；
2. 第二个 natural invalid-dominator expansion；仍只有 R50H 真正触发错误删除与 wave1 恢复；
3. COCO mAP、物理 AXI 流量、整网 FPS 或跨 boot YOLO 稳定性；
4. Cheng 2026 的源码级 weight reuse；本地仍是 barrier 功能级实现。

P7R444 已完成本报告所列的最终 allowlist 命令容量收尾：Y10 oracle 整图实测 instruction/UOP 峰值
为 1,065,280/1,320 B，页对齐为 1,069,056+4,096 B；三 seed 的 8 输出在缩容后全部精确匹配，
instruction 少一页时在违规提交前拒绝。下一优先级因此只剩增强项：Y10 独立 boot 复验，或寻找
第二个自然错误支配点；不再利用已经暴露的 Y10 标签调整排序规则。
