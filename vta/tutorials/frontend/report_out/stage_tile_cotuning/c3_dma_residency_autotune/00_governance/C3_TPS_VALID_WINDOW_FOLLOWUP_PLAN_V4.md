# TPS双银行有效窗口聚合后续实验计划

状态为下一轮设计稿。本次只制定计划，不生成新候选、不运行FSim或FPGA、不修改历史封存结果。

研究名称继续使用“片上数据有效窗口约束的VTA跨微内核聚合方法”。下一轮先验证：**已有双缓冲程序中的两个银行，在保留通知方向、数量和数据安全关系时，是否允许先等待两份数据，再把两份计算连接起来，最后分别释放两个银行。** 合法也可能变慢；研究必须分清通知位置变化、命令聚合和完整调用净收益。

主要对象为已封存的Banerjee式TPS节点24；迁移对象固定为已审计的官方YOLO416对应层。保持各自原Tile、线程、张量装载和完整融合语义，不再全量重审两网、不生成新的TPS配置、不按时延补选程序。

这里的“银行”（bank）指原程序为两个虚拟线程安排的片上数据分区。例如TPS共享输入区，分别使用两份权重与累加区；本轮沿用这些分区，不重新设计双缓冲。

## P 冻结目标与实验对象

### 1 三个研究问题

**能不能合？** 两个银行的输入与权重是否都已就绪，ACC是否独立；把内部等待提前、释放推迟后，必要数据先后和有限队列中的执行进度是否仍正确。

**能合多少？** 以本来的换数据、RESET、后处理、STORE和提交边界停止，核对连接清单、指令字段和缓存生命周期。本轮只探讨原程序中的双银行窗口，不搜索第三份、q或切点。

**合了值不值？** 同一完整融合程序内，以三个变体分别测量通知外移的影响、在相同通知约束下聚合的影响，以及整套方案相对原版的净收益。较少GEMM不能代替完整调用测量。

原[目标V3](C3_OFFICIAL_VALID_WINDOW_OBJECTIVE_V3.md)中“进一步降低官方重实例化程序完整调用时延”的目标保留，由官方对象的G对B回答。TPS提供较强复用底座及自然容量现象；它不是TopHub，也不是全搜索空间最优。

### 2 既有结果与本轮支持域扩展

上一轮在“不跨原host循环迭代、不移动内部通知”的支持域内，26个官方完整融合实例的A/B全部相同。这不证明通知永远不能迁移，也不证明两个网络的任何执行程序都没有机会。[上一轮报告](../07_grouped_holdout/20261014_c3_official_valid_window_run01/REPORT.md)保持不变。

本轮唯一方法扩展是**有证书的双银行通知外移**：只对指定窗口的就绪消费和银行释放作位置调整，保留通道、数量、配对次序和原消费者；不删除“看起来多余”的token，不开发通用通知优化器。

空间、CI分组、输出外组的host循环顺序仍固定。对官方程序中编译器产生的两次虚拟线程银行执行，只建立有限分析视图；若需形成聚合表示，只允许连接该固定银行轴，不能顺便跨其他循环迭代。线程来源须由编译链和配置证明，不能把任意extent=2的For当成双银行。

通知外移会改变最早启动和释放机会，涉及原五类因素中的③与⑤。本轮把它们作为聚合的必要连带变化，用N单独对照；①输入/权重复用、②空间安排和张量LOAD粒度保持不变。不再声称B到G是完全没有控制变化的单因素实验。

TPS以封存的post-Fold父IR为源；官方对象以[原父IR](../07_grouped_holdout/20261014_c3_official_valid_window_run01/baseline/yolov3_tiny_416_final01/B_raw/parent_003.tir)为源，保持完整官方配置实体与来源记录。先完成无变换往返，核对ABI、线程、全部张量请求、GEMM/ALU、硬件循环、提交和缓存身份共享关系。

## D 先验证一个窗口 再形成完整程序

### 1 首先检查真实通知编码代价

用就绪消费R和释放F说明三个表示；R不是新张量装载，原张量LOAD顺序始终保留。

```text
B原版：R0 → K0 → F0；R1 → K1 → F1
N通知：R0、R1 → K0、K1 → F0、F1
G聚合：R0、R1 → GEMM(K0、K1) → F0、F1
```

先证明产生R1的数据装载不依赖窗口内部F0。若存在“等待第二份数据，而第二份数据必须等第一次计算释放”的循环，就保留原边界；不通过移动张量LOAD、新增缓冲或同步解救候选。

VTA指令每方向的通知字段是bit，不能用一个bit表示同方向两个token。本地runtime重复DepPop会提交等待NOP；重复DepPush也可能插入NOP。因此先生成实际编码清单：通知数量不能减，NOP必须计入总指令，不能只展示GEMM减少。

零长度UOP类型NOP保留其FIFO和依赖作用，但不计有效μop装载、不参与DRAM序列化源基址推断。诊断器必须区分真实UOP LOAD与承载token的NOP。[本地编码依据](/home/orange/code/tvm/vta/runtime/runtime.cc:1581)。

### 2 TPS首窗口预实验

从第一个输出外组、第一个CI组的两个银行开始，仅作离线预实验；其余计算原样保留，不测局部microkernel时延。

既有两份清单各2352条μop，共同硬件循环为4和3，ACC范围分别为[0,784)与[788,1572)。如果全部条件通过，连接清单4704条，小于8192。只改变本来两个完整kernel的表示，不把一个kernel先拆碎再合。

逐项验证：

1. 两个银行的INP/WGT版本在新入口确实就绪，最后读取完成先于覆盖；共享输入只读，WGT与ACC区域关系明确。
2. ACC初始化、每输出乘积项及重数、归约整数语义、后处理和STORE完全一致。硬件循环连接会改变两银行之间的交错次序，必须逐输出认证。
3. 每个ready token及release token都映射到原数据就绪或银行再用事件、原消费者、通道与序号；实际承载指令重新绑定，不要求迁移后的指令号相同。F提前错误拒绝，F延后必须重新检查阻塞与进度。
4. 实际编码的FIFO/token图无环，且在有来源的有限指令FIFO和token容量下没有可达死锁。只证明DAG无环或运行一次FSim不够；模型限于该有限序列，不开发通用调度证明器。
5. 单kernel容量、exclusive end、有效地址、循环字段、空/单int32签名0..98与不同段缓存身份成立。
6. 新连接点、循环进位及指令边界的ACC依赖合法。保留VerifyDep；不能从FSim一致反推硬件间隔。

有限阻塞检查最多100万可达状态，单作业8 GiB、600秒；超限登记支持未决。缺少可信FIFO容量或操作启动/完成规则时，不采用猜测参数认证。

已有[硬件合同](../07_grouped_holdout/20261014_c3_official_valid_window_run01/HARDWARE_CONTRACT.md)仍有冻结bitstream来源未决。先只读核对已有构建档案、源指纹、综合报告和bit配置数据；文件名或大小相同不足以闭合。若差异只在文件头，应通过完整配置数据字节及来源链证明，不能仅凭推测。若采用相对ACC安全证明，也必须绑定冻结发射/完成语义，不能把μop距离直接换成时钟间隔。硬件依据仍未决时可以封存本地逻辑/FSim诊断，但停止新G上板，不换bitstream、重新综合或试测反推安全。

### 3 形成自动的完整B/N/G

首窗口门禁通过后，在原扫描顺序下自动处理同类合法双银行窗口。识别依据为数据版本、地址区域、ACC阶段、编译线程来源与依赖；不依赖Node24、变量名或固定四对窗口。

N和G必须使用**同一份已认证窗口清单**。N保留原kernel、μop内容、硬件循环及host缓存身份共享关系，只调整通知。G在此基础连接清单；其缓存和装载变化属于聚合连带成本。无法保持N的控制变量时，不把N/G称为干净对照。

遇到CI换组、输出外组、RESET、ALU、STORE、提交或未知关系立即结束。TPS的第三份计算跨越换数据，不能因为2352×3≤8192就连接三份。

| 表示 | TPS全窗口均通过时的结构预期 | 官方全窗口均通过时的结构预期 |
|---|---|---|
| B | MAC 8、单kernel 2352 | MAC 512、单kernel 39 |
| N | MAC仍8、单kernel仍2352；实际NOP另计 | MAC仍512、单kernel仍39；实际NOP另计 |
| G | MAC由8降至4、单kernel最大4704 | MAC由512降至256、单kernel最大78 |

这些是结构假设，不是验收配额；部分窗口必须保留时如实报告。RESET、ALU与张量访问任务保持，不为达计数跨边界。没有q性能扫描，也不选择“只合最快的一对”。

官方对象的两次虚拟线程执行首先仅作分析视图。N保留原GEMM initializer与签名共享关系；不能把源展开导致的缓存/闭包收益误记成通知或聚合收益。若这一表示适配无法无损表达，登记未决，不强制支持。

### 4 专门记录容量现象

TPS两份4704条清单无法同时全部放入8192条SRAM，但每份都合法；必须认证真实回绕、驱逐、重新装载及在途读取。不要把host清单总量、序列化量、UOP LOAD累计量混为同一个数。

分别列首次装载、容量驱逐后重装、提交Reset后重装和身份失效；保留DRAM源至真实完成，不能只检查SRAM地址。新LOAD与所跨计算引用冲突时禁止该次greedy前移，B/N/G共同使用同一正确性底座。

官方39到78的连接提供原清单较小的对照，但不预设零容量压力，必须由新native证据确认。两对象内部各自做因果比较；跨对象差异只说明案例条件，不拟合五因素模型。

## C 正确性门禁与固定小池测量

### 1 本地门禁

先精确认证完整函数的产品项、数据版本、整数语义、张量描述符、全部提交、缓存身份和逐μop引用，再做三seed完整融合FSim、同实际权重存储W0→W1→W0及定向低饱和/阈值输入。

定向用例记录非零未饱和输出数、零比例和clip端点比例；每次调用前预填不同输出哨兵。W1必须先由独立参考确认至少一个最终输出改变。每版最多500万展开μop步骤，包括RESET和ALU；所有重枚举串行，单作业进程树8 GiB、600秒。

沿用最多16次已解释完成提交的证书，延续跨提交数据/ACC和DRAM身份；未知AutoSync切点拒绝认证。新增候选必须详细采集实际编码；不能用旧模块的cold定义证明新模块warm内容。

新增针对性反例至少包括：第二份就绪依赖首份释放造成循环、同方向两token被错误压成一个bit、有限FIFO背压死锁、共享地址但不同数据版本、两个ACC区域存在交叉依赖、硬件循环进位非法、三份跨换装被错误拼接、零长度NOP被当成有效UOP LOAD、缓存同身份不同内容。每例明确通过、拒绝、保留边界或未决。

### 4 三种性能效应分开报告

```text
x[r,p,s]    = 当轮、程序p、seed s的唯一正式时延
m[r,p]      = 三seed的x中位数
T[p]        = 六个m中位数
gain_r(X,Y) = 100 × (1 - m[r,X]/m[r,Y])
Gain[X;Y]   = 六个gain_r的中位数
```

| 对照 | 可回答的问题 |
|---|---|
| N对B | 通知外移及其NOP承载的整体影响 |
| G对N | 在相同入口/出口通知约束下，聚合和必要缓存/循环表示变化的影响 |
| G对B | 整套方案的完整调用净收益，主要性能结果 |
| Q8对Q1 | 已知特化机制在本轮条件下是否仍成立 |
| Q8对TPS B/G | 同一224任务的实用程序比较 |

每对象分别报告六轮变化、绝对毫秒差、胜场、范围与离散度。比例改善不能相加；N/B的差额不能直接命名为纯流水损失，G/N的差额也不是纯CPU命令成本。

TPS和官方各自的主要净收益工程门槛均为G对B的Gain≥2%、胜≥5/6。G对N过门槛但G对B未过，只支持受控通知安排下的组织收益，不能称完整方案加速。官方G对B通过，才支持该TopHub缓存重实例化程序得到改进；TPS结果不替代官方结果。单启动六轮不称统计显著性或独立复验，不换算整网FPS。

诊断表单列有效MAC、RESET、ALU、控制NOP、真实张量LOAD/STORE、有效UOP LOAD、单kernel大小、序列化量、回绕/驱逐/重装原因和提交。性能剖析不能分解的成本保留未解释，不把命令减少直接换算周期。

## A 封存适用边界并决定下一轮

交付两银行窗口规则、通知及阻塞证书、乘积/整数等价证书、真实缓存生命周期、明确反例、同父IR血缘、冻结池、逐调用账目和完整结果。用实际发现形成有条件的机制结论：

同时公开本轮固定对象的状态链：来源与往返成立→首窗口分析完成→通知与硬件合法→完整程序认证→N/G表示不同→入池。身份失败、分析资源限制、支持未决、合法但无机会和无性能收益分别登记；两个固定案例的结果不能替代两网全体结论。

| 可能结果 | 可保留的结论 |
|---|---|
| 数据都有效，但通知无法外移 | 数据驻留是条件之一，原边界承担执行进度要求 |
| 能合两份，第三份因换数据结束 | 容量上限与实际有效窗口不同 |
| GEMM少了，NOP或重装增加 | 单项命令下降不等于完整组织成本下降 |
| G快于N，仍慢于B | 聚合收益被通知外移及关联成本抵消，应保留原安排 |
| G快于B | 在该固定程序和已认证窗口上存在净收益，不推广全部网络 |
| Q8仍快于Q1，却慢于TPS | 机制收益与实用竞争力分开成立或失败 |

这些是限定案例中的机制结论，不是普遍规律、全空间最优或五因素预测模型。Banerjee已有复用、容量、依赖和runtime优化；贡献仍落在自动识别哪些通知可外移、哪些必须保留，以及合法分段和公平完整调用证据。

有净收益时封存相同程序、来源和适用条件；独立启动复验另行设计，不重新选配置。无收益或不安全时保留负结果、收窄方法支持域。当前不做整图部署、新AutoTVM搜索、Tile或驻留比例调整、预取、selector、runtime签名扩展或硬件改造。

优先执行顺序为：**一个TPS窗口的本地证书→完整TPS B/N/G→固定官方层迁移→冻结小池→FPGA资格及单启动计时→封存暂停**。阶段失败就在该阶段结束，不继续扩大实验池寻找正结果。
