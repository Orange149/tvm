# 冻结实验协议 v1

本版本的实验协议和执行策略均为 v1，由 `plans/board_execution.json` 和控制器源码哈希冻结。阶段编译与原生构建绑定实际 SDK 工具链身份，原生构建缓存按身份隔离，随包 SDK 库核验来源与哈希。源码、SDK 或实验规则变化时须生成新包和新 run，不能混用不同身份的数据。

离线分析也须使用与 `state.json`、部署包 manifest 一致的控制器源码、Python 版本和 numpy/scipy/matplotlib 版本。校验发生在任何分析文件写入之前，即使确认窗口不完整也不跳过；`analysis.json` 和 `cost_accounting.json` 的 `provenance` 记录 bundle ID 与控制器身份。直接调用单环境分析同样受此约束。

## 研究问题与边界

检验“卸载 VTA 计算仍占用主机 CPU 工作”能否改变划分选择，以及改进是否已可由通用核心容量约束或简单主机隔离解释。结果用于判断继续研究方向，不能自动推导会议录用或论文新颖性。

一次共同量化、21 单元、CPU 首尾、相邻设备交替、最多 3 个 VTA 岛。原始合法域包含 4,623 个拓扑、972,528 个共享核配置；CPU 85 段、VTA 87 段。所有组使用相同成功编译域。残差等多输出通过完整 live frontier 传递，逐条检查输入输出节点身份、形状和类型。

共同数值参考来自相同规范图的独立 AArch64 CPU 整图与完整边界探针，两者须在全部 67 个输入上输出一致。首层浮点计算的架构差异会跨越整数舍入边界，因此不以 x86 输出作为 ARM 整数边界的精确参考。输入及其顺序保持冻结，整数仍逐元素精确比较，浮点容差不变。参考来源证明和程序身份随包保存；不把待测划分自身的输出写成参考，也不从历史参考实验导入成本或性能数据。

CPU 的 t 个线程使用前缀核集合 `{0,…,t−1}`。共享组 VTA 主机可使用全部 P 核。D 的 CPU 使用前 P−1 核、主机专用最后一核，并重新枚举 t=1,…,P−1。4 核共有 15 个非空核心子集，2 核共有 3 个。

## 模型与记账

时间均为毫秒；核时为孤立、串行会话的进程 CPU 时间。单段 `service = set_input + run + get_output`。每段拥有自己的 set/get 核时，各记一次；不能再按边界加一份复制核时。

令 `S=max(max CPU段 service, Σ全部VTA段 service)`；VTA 全局互斥覆盖 set/run/get，因此必须累计所有 VTA 岛。`Wc` 为 CPU run 核时，`Wh` 为 VTA run 主机核时，`Wb` 为所有阶段 set/get 核时。旧局部约束 `Acpu=max_k Σ(t_i≤k) Wc_i/k` 只约束 CPU run。

| 组 | 评分 |
|---|---|
| R | S |
| C | max(S, (Wc+Wb)/P) |
| H | max(C, (Wc+Wh+Wb)/P) |
| A | max(C, Acpu) |
| O | max(H, Acpu)，保持旧完整模型公式 |
| G | max(S, max_A Σ(Aj⊆A) Wj/|A|) |
| D | 使用专用主机核重新联合搜索，同 G 的容量公式 |

G/D 对 CPU 计算、VTA 主机和边界统一记账。任务核集合为其实际允许 affinity；它是流体容量近似，不保证预测值等于实测 II。DDR 项、DMA 二次排名、CPU 阶段门控均关闭。固定普通复制、调优历史、Tile、队列深度 2、spin 0、nice 0、禁用 replay，主环境 poll/post-start 均为 1,000 ns。

排序采用完整域评分，无启发式剪枝。分数按 1e−9 ms 归一化以消除浮点加和顺序误差；同分按完整配置 ID 字典序。保留 Top-20。CPU 85×4、VTA 87×2 共 514 个主环境执行签名；每个签名单独标定，VTA 两类主机掩码不混用。

## 数据及启动

64 张真实输入的前 16 张只用于组件成本，后 48 张只用于性能。另有 3 张诊断输入。资格检查允许对完整 64+3 输入做数值核验，不使用其时延生成成本。每个已编译阶段在首个标定启动核验前 16+3 张完整输出；候选组合在性能前核验诊断输入全部阶段输出。整数逐元素精确一致；浮点 rtol=1e−4、atol=1e−5。

所有会话逐帧验证 `input_index = frame_id % 输入池长度`，资格检查还要求完整覆盖规定输入池。回收的 `inputs.txt` 必须与冻结任务生成的输入清单完全一致。同一输入重复运行不能替代多输入核验。

标定两次独立启动，各两轮：每个签名 5 帧预热、32 帧计入。每轮保留原始 set/run/get 壁钟和进程核时，按两轮、两次启动均衡平均生成新成本表。板端成本身份必须包含 bundle ID、资源环境和两个不同 boot ID；禁止历史和合成表进入真实排名。

筛选使用两次新启动，每次两轮，各组 Top-5 并集，加按 1/2/3 岛分层随机的各 4 个配置，随机配置排除 Top-5 并集，最多 47 个。每层用容量 39 的均匀蓄水池，完成枚举后按同一随机流打乱池内顺序，再排除 Top-5 并集并取前四个；不足 39 个候选的层也打乱。随机种子 20261023；若收缩域某层不足 4 个，则如实报告该层实际数量。

筛选后冻结每组静态 Top-1（预算 1）及各组前五中按筛选 II 选出的配置（预算 5），同分按配置 ID。确认使用另外六次新启动，各两轮，最多 14 个配置。同一配置在同一启动共用测量，方法选点相同须报告零选点差异。

正式窗口运行 340 帧：前 20 帧预热、后 20 帧排除，中间保留 300 个完成时间戳，形成 299 个相邻完成间隔。II 是这些间隔的均值，latency 单列。首个标定启动在固定锚点比较 20 与 100 帧预热，II 差异超过 2% 时，该环境统一使用 100 帧预热、总帧数 420；这一规则在筛选前冻结。

每轮前后测固定锚点；相对漂移超过 5% 则整轮失效，原始记录保留，最多补两轮。程序按固定种子打乱顺序；确认数据不回流成本、排名或选点。实际内核 boot ID 是独立性依据，测试进程重启不增加启动数。

远端测量与部署哈希校验、压缩流解包、日志打包及结果清理共用启动范围内的锁。断线后若会话仍运行，仅轻量查询状态；重型恢复操作等待会话结束。包装进程收到 HUP/INT/QUIT/TERM 后禁用退出清锁，保留该启动的锁；KILL 退出也保留锁。部分 shell 延迟到前台子任务返回后才处理信号，期间锁持续生效。正常完成及普通命令失败可以释放锁。锁占用时只在电脑记录回收暂缓，不在板端打包活动窗口的文件，也不回收同一启动的遗留锁。

## 诊断与资源敏感性

从筛选池预先选三个拓扑：1 岛主机工作低端、2 岛中位、3 岛高端。每对先把 CPU 线程数固定到不超过 P−1，再比较主机共享全部核与专用最后一核，两边 CPU 的线程数和掩码完全相同。这与 D 的联合搜索结果分开解释。

确认启动中分别测无详细日志、开诊断两种会话。`--session-profile-window FIRST,COUNT` 在第一个保留完成点启动，在最后一个保留完成点停止，包含所有当时存在的线程。使用 TID 与阶段归属匹配 runtime、runqueue_wait 和上下文切换；同时保留队列与 VTA mutex 时序。原始 JSON 的 `whole_process_existing_threads` 表示线程范围，采样时间范围由任务窗口明确记录。休眠池线程数与 `runtime.NumThreads` 的活跃线程数分别记录。

每对诊断先核验 shared/dedicated 两种组合的全部诊断输出。四个条件 shared/dedicated × plain/profile 采用冻结种子产生顺序，确认启动 1/2、3/4、5/6 分别使用一组顺序及其反向顺序，因此六次启动中各条件的平均位置相同；三种拓扑块的次序也反向配对。每个四会话块前后测锚点，漂移超过 5% 作废整块，最多补两块。顺序、补测次数、前后锚点和失败块均留档；同启动续跑复用已完成块，意外重启则整体作废该启动。

若日志扰动任一配对超过 2%，对应诊断不支持自动机制继续条件。三种拓扑的隔离比较作独立 Holm 校正；机制继续条件要求至少一对隔离 II 改善 ≥5%、校正显著、主机线程观测完整且 runqueue_wait 下降。PMU 不可用时如实记录；不把轮询时间当纯硬件时间，不把残差全归因 DDR。

资源环境为 P=2/4 × poll=0/1,000/100,000 ns，post-start 均为 1,000 ns。核数指实验工作线程可用核数，不热拔插其他核。主实验同一个预算下 O 对 H/G/D 全部达到改善门槛，且机制条件通过后，再推进剩余五种环境；每种重新标定、排名、筛选、确认。主环境直接复用。

## 统计与判断

每配置先在启动内平均两轮 II，再以六个启动为样本配对 `log(II_other/II_O)`。报告配对 t 的 95% CI、几何均值意义的 II 改善。O 对 H/G/D × 预算 1/5 共六项主要比较作 Holm 家族校正，α=0.05。改善 ≥5% 且校正显著且 CI 下界 >0 才通过投入门槛。

轮次和诊断汇总中的每个测量及锚点携带 `_receipt` 相对路径与 SHA256，关联已接受凭据、冻结任务和原始文件哈希。分析与轮次复用前核验这些关联。确认必须有六个不同 boot ID，每次恰好两轮、包含完整选点池；每份诊断必须对应同一确认启动，并包含预定诊断条件和有效锚点。缺文件、重复或错配启动、汇总与凭据不一致均停止推断，不能靠文件数量满足统计门槛。

非显著不等于等效。另以配对 log-ratio 的 90% CI 检验 II 比值落在预设 [0.95,1.05] 内，即 α=0.05 的双单侧等效规则。同配置比较精确记录零差异。六个启动的推断能力有限，报告 CI，不将 299 个帧间隔当作 299 次独立实验。

主机工作消融另外输出 H 对 C、O 对 A，各含预算 1/5，四项构成单独的次要比较家族并作 Holm 校正；采用同样的 ≥5%、校正显著和 CI 下界 >0 规则，单列 `host_work_gate`。O 对 H 检验局部 CPU 容量约束的选点收益，单列 `local_cpu_constraint_gate`，不能标为主机工作效应。这些消融结果不替代六项主要比较的投入门槛。

`performance_gate` 只在同一预算下 O 对 H/G/D 全部过门槛时为真，`eligible_budgets` 列出满足条件的预算；不能跨预算拼接收益。研究方向的“继续方法研究”与 `continue_sensitivity` 完全使用同一条件：`performance_gate` 且机制条件通过。性能条件通过但机制未确认时单列“性能收益成立，机制未确认”；只有部分消融收益时报告“存在效应但通用约束/隔离解释尚未排除”；其余报告“证据不足”。主机工作消融是否成立始终单列，继续建议不替代这项证据，也不替代论文相关工作和创新性论证。

成本记账按 `(boot ID, task ID)` 统计，同一会话多次回收的完成帧按 frame ID 去重。`accepted_native_frames` 为通过会话核验的帧数；`observed_completed_frames` 包含失败、废弃启动和被漂移规则作废轮次的已观测完成帧。全部会话都有完整帧证据时才填写 `actual_native_frames`；存在部分回收、缺文件或未完成会话时该字段为 null，`native_frames_status=lower_bound`，并列出未知会话。零观测不代表零消耗。启动数包含失败会话，另外单列接受凭据的启动数。
