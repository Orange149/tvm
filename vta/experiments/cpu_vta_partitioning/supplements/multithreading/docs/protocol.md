# 冻结协议 v1：ResNet18 多线程与核心映射

## 范围和身份

配置为 `configs/resnet18.json`，随机种子 20261102。共同图为 21 单元，CPU 首尾、设备交替、最多 3 个 VTA 岛；使用父包成功编译的全部 85 个 CPU 段和 87 个 VTA 段。每个配置身份包含阶段、线程数、实际核心集合、CPU 执行模式；环境和程序身份再纳入测量任务哈希。

两种环境：四核计算且 VTA 主机可使用四核；CPU 仅使用 0–2 核、VTA 主机仅使用第 3 核。轮询和 post-start 均为 1000 ns，队列深度 2，线程池 spin 0，nice 0，普通复制，禁用 replay。两种环境在同一板子启动中测量，相邻启动反转环境顺序。

本对照是 Tarnawski 论文物理 CPU 设备模型在共同阶段域上的适配，补齐一致的 CPU 交接与 VTA 主机核时记账。阶段融合与 legal frontier、固定 VTA bitstream、最多三岛均为共同平台限制，不宣称复现原论文任意算子 DAG 的全部设备放置算法。旧阶段独立评分不称为原论文完整实现。

## 评分

阶段壁钟服务为 set_input、run、get_output 之和。阶段计算核时来自孤立串行会话的进程 CPU 时间，交接核时为该阶段 set/get 的 CPU 时间。每阶段自己的交接只记一次。全部 VTA 段共享同一互斥设备，其壁钟服务总和必须累计。

共同阶段约束取“最慢 CPU 阶段”和“全部 VTA 服务总和”的较大值。总容量约束为全部 CPU 计算、全部交接与全部 VTA 主机 run 核时之和除以四。专用主机环境还分别约束 CPU 任务的计算与交接核时除以三、VTA 主机及 VTA 交接核时除以一。

单线程物理映射及两种固定组方法：在共同阶段与总容量约束上，增加每个 CPU 核心组内部阶段壁钟服务的累计值。每阶段线程数为组宽，多个阶段可共用同一组，不同组必须不重叠。枚举全部物理分组；未被使用的组不产生新的配置身份。无门控版本的累计服务是评分近似，不能声称执行器实现了论文的串行设备调度。

重叠核心组＋总容量：任意核心集合，采用共同阶段和总容量约束。重叠核心组＋全部子集容量：对四个物理核心的全部 15 个非空子集，累计允许核心集合完全包含于该子集的任务核时，再除以子集核数。CPU 计算、CPU 交接、VTA 主机与 VTA 交接采用各自阶段的实际允许集合。流体容量是近似，不保证等于实测完成间隔。

现有方法仅搜索前缀核心集合。四核共享保留原完整模型：共同阶段约束、全部工作核时/4，以及对每个前缀大小 k 累加线程数不超过 k 的 CPU run 核时/k；局部项不追加 VTA 主机或交接。专用主机环境保留原专用核方法的子集容量公式。两种环境均使用新标定输入，不改变旧公式。

旧简化对照仅采用共同阶段约束，不作公平优势的主要依据。全部排序按 1e−9 ms 归一化并按完整配置 ID 处理并列。前 20 与前 5 均按包含执行模式的配置计算预算，不能把两种模式当作一次测量。

## 执行与数据

`resource_group` 模式只用于固定核心组串行对照。同组 CPU 阶段在 set/run/get 及输出快照范围内 FIFO 互斥；等待在阶段服务范围外。不同不重叠组独立并行。部分重叠组在该模式下拒绝。各串行选点还以完全相同的阶段、线程和核心集合关闭门控复测，单列执行机制效应。其余正式方法和核心干预关闭 CPU 门控。

前 16 张真实输入用于组件标定，后 48 张用于性能评价；另 3 张用于诊断。每种签名首个标定启动核验前 16+3 张完整 frontier。每次启动核验锚点的全部 64+3 输入，每个进入筛选/确认的组合核验 3 张完整诊断输出。整数精确比较，浮点 rtol=1e−4、atol=1e−5。所有帧核对输入序号，线程池实际活跃数与线程 affinity 必须符合配置。

两次标定启动各两轮，签名预热 5 帧、计入 32 帧，四轮均衡平均产生 1,449 种签名成本。CPU 相同签名在两种环境中的隔离执行条件相同，复用该条记录；两种 VTA 主机掩码分开标定。历史/合成成本不可用于真实排名。原始记录保存 set/run/get 壁钟和核时，组件表与加速曲线不代替并发确认。

两次筛选启动、每次两轮。各环境六种方法前五的并集加每个岛数量 4 个随机配置；随机对照从完整域等概率优先级样本中选取，排除前五并集。每层保留 42 个优先级最小的候选再随机打乱取前四，保证足够排除最多 30 个重复项。筛选后冻结静态第一名及前五中筛选完成间隔最好的配置。

固定划分四格取单线程映射和任意核心子集方法的静态第一名拓扑，在两个拓扑上分别按标定选出最佳单线程和最佳多线程映射。两条跨格映射在确认前冻结；相同拓扑/配置共用测量。

核心干预固定 CPU 0–2、VTA 3–17、CPU 18–20。四核环境为两个两线程阶段同用 {0,1}，对照分别用 {0,1}/{2,3}；三核环境为两线程阶段 {0,1} 与单线程阶段 {0}，对照改为 {0,1}/{2}。VTA 放置、线程数、切图和执行方式均不变。详细日志会话另测，不代替无日志性能。

历史复核固定旧三岛配置的 CPU 线程 4/3/3/3，以及旧单岛配置的 CPU 线程 4/2，在本轮四核环境下重新测量。旧 45.67% 是一次历史内核启动内的三轮吞吐结果，本轮使用六次新启动单独报告。

## 窗口与统计

正式窗口 340 帧，去掉首尾各 20，保留 300 个完成时间戳、299 个间隔。首个标定启动对锚点比较 20/100 帧预热，差异超过 2% 则该环境统一预热 100 帧、总帧数 420；筛选前冻结。每轮/诊断块前后测锚点，漂移超过 5% 整轮/整块作废，最多替换两轮/块，失败数据保留。确认六个新启动各两轮，先启动内平均，再以启动为配对统计单位。

现有方法分别对单线程物理映射、固定组无门控、通用子集容量，覆盖两种环境及预算 1/5，共十二项，Holm 家族校正，α=.05。至少 5% 完成间隔改善、校正显著且 95% CI 下界大于零才通过投入阈值；同一环境、同一预算的三项必须共同通过。次要比较单独 Holm；核心放置干预的两项另作 Holm。±5% 实际等效采用 90% 配对 log-ratio CI 的双单侧规则。

机制支持还要求核心分开后调度等待下降、全阶段 TID 观测完整，且详细日志的任一扰动不超过 2%。非显著不等于等效。配置相同报告身份一致，不声称独立测量证明模型理论等价。

同一个 kernel boot ID 不可用于下一阶段；进程重启不算独立启动。SSH 断开后接续原任务并复用已接受凭据，不再次计入窗口；意外板子重启则保留并废弃整个未完成启动。任务失败、哈希错误、重复帧、缺文件、错 boot ID 均停止接受。
