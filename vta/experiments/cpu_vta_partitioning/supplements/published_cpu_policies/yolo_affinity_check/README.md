# YOLO绑定方式匹配验证

固定 CPU0–2 → VTA3–6 → CPU7–8 → VTA9–12 → CPU13，比较4/3/1重叠和3/1/1分组下的逐线程固定与核组内迁移。所有CPU门控关闭，主机和控制线程共享四核，使用原等待路径。

入口为 `run_yolo_affinity_check.py`。先 `audit`、`prepare`、`validate`，然后 `board run --execute-board`；中断后使用 `board resume --execute-board`。`status` 查询，`analyze` 从原始凭据重放并生成表格与图。

4项CPU前段各资格检查1帧、预热2帧、计入8帧；4项流水各资格检查1帧、两轮8/64/32窗口。总计20个板端原生会话、836次完整DNN、44次隔离CPU阶段调用。第一轮按20261110随机化，第二轮反向，新进程执行。空回调、初始化和本地QEMU调用单列。

两模式始终使用同一个执行器。每个进程计时前主动探测logical worker→TID→允许集合，性能窗口不加详细探针。迁移模式不使用固定worker_core_map，不能凭核心编号反推线程身份；许可不代表已经观测到迁移。

本批封存后的分析器有两项只读兼容修正：回收目录应为任务目录下的 `transfers/<generation>/collected`；线程时钟作用域需要与组件／流水类别使用不同字段。后续统一使用 `run_yolo_affinity_check_analysis_compat.py`，参数同原入口；它对分析应用这两项修正，其余命令委托原入口。原冻结源码及失败分析日志保留，测量任务、原始记录、程序和窗口均未改变，也未因此重测。

只用输入0、同一次boot；不自动重启、加锚点、漂移拒收或加测。错误输出、绑核、哈希、boot和帧完整性均拒绝。每任务哈希区分轮次，续跑重新核验已接收原始凭据，不重复执行。

单启动两轮为机制探索，不报告显著性；不修改隔离成本、评分、DP、Top-20或任何旧批次，也不自动推广绑定模式。
